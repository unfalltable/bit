## 本次实现

新增 `crates/bit-state`，底层直接使用规格选定的 Cnidarium 0.83.0、JMT 0.11.0 和 RocksDB 8.1.1。状态层将高度、执行摘要、compact 摘要、Penumbra TCT 根与可恢复 frontier、anchor、nullifier、tx_id、供应会计、费率配置和逐项质押记录放进同一个原子提交批次。状态高度必须与存储版本一致，链上下文、本币 asset ID、协议版本、区块字节上限、交易限制、anchor 窗口、有序创世隐私承诺摘要、货币政策、费率和质押参数在创世后不可变，重启配置不一致会拒绝打开数据库。当前 schema 为 v7。

Transfer 校验已拆出无状态密码学入口，以便异步状态层先做廉价的网络、anchor 和重放检查，再验证证明与签名。每笔交易的 commitment 先在 TCT 副本中全部插入，随后才写 StateDelta；重复 tx_id、交易内/同块/跨块 nullifier、非法 commitment 都不会留下部分状态。

状态提交采用 `prepare_commit`/`commit_batch` 两阶段：Prepare 只计算下一 JMT 根，Commit 才执行 RocksDB WriteBatch。测试模拟 Prepare 后丢弃并重启，数据库仍停在旧版本；重新执行相同区块得到相同 app hash。查询接口返回 Cnidarium 原生 ICS23 证明，测试覆盖主 JMT、shielded 子 JMT 的成员证明和非成员证明。

真实证明链路已接入持久化状态：测试生成两笔创世输入票据和一笔 2 Spend/2 Output Transfer，校验四份 Groth16 证明、两份 Spend 授权与 binding 签名，把两个 nullifier、两个新承诺和 tx_id 原子提交到 RocksDB。关闭并重开数据库后，高度、app hash、TCT 根、nullifier、tx_id 及 ICS23 证明保持有效；下一高度重放同一 envelope 被拒绝。

Windows GNU 构建补齐了项目内 `libclang.dll`、libc++ include 和 C++ 标准库选择。`bootstrap_tools.py` 已固定 LLVM-MinGW 与 libclang wheel 的 URL 和 SHA-256，不依赖全局安装。

新增 `crates/bit-app`，实现 ABCI 网络层之前的统一生命周期核心。CheckTx 无副作用，PrepareProposal 按链上与请求字节预算筛选，ProcessProposal 在同一临时视图按顺序重执行，FinalizeBlock 产生稳定逐笔结果和单个待提交批次，Commit 才持久化。协议版本和最大区块字节数已进入创世持久配置，避免重启使用不同本地限制。

`bit-app` 已接入固定的 tendermint-abci/proto 0.40.4 v0_38 类型。InitChain 与预配置请求逐字段核对并校验基础共识参数；Query 将本地自验后的 ICS23 commitment proofs 编码为 `jmt:v` ProofOps；vote extension 只接受空值；未实现的 State Sync 快照显式拒绝。多个 ABCI socket 线程通过共享执行锁进入同一状态机，致命状态错误会设置全局 halted 标志，监听接口只允许 loopback 地址。本机 TCP 测试已覆盖 Info → InitChain → CheckTx → FinalizeBlock → Commit → proof Query。

新增 `crates/bit-emission`，实现 1024 亿 BIT 固定上限和七类资产容器的整数会计。每次创世、变更、Prepare 和重启都会核对 `T = Q + ΣP + D + ΣX + ΣC + F + G = G0 + Mint - Burn`、`Mint + K = U(e)` 与剩余发行预算。逐 epoch 正常额度进入费用池，空合格集合额度永久放弃且不追补；销毁不会重开发行额度。

Transfer 的公开 fee 已贯穿无状态验证结果和持久化执行：状态层在副本上执行 `Q -= fee; F += fee`，与 nullifier、output commitment 和 tx_id 同批提交。真实 2 Spend/2 Output fixture 的 1,000,000 原子单位 fee 已验证入池、ICS23 证明和重启恢复；费用不足不会留下交易或会计写入。测试还直接篡改落盘费用池，确认节点重启会因供应恒等式失败而停止打开。

最低费计算已按完整规范 envelope 大小向上取整到 KiB，并叠加 Spend/Output proof 数量及创建持仓、注册验证者附加费。六项费率进入当前 schema v7 并可生成 ICS23 证明，重启配置不一致会拒绝打开。低费交易在 Groth16 前以稳定错误拒绝，交易记录同时保存实际 fee 与当时 minimum fee。

发行计数现已与提交高度强绑定：`completed_epochs = max(0,(h-1)/epoch_blocks)`。高度 721 才结算首个 720 块 epoch，不能在高度 720 提前发行。D007 的真实签名得分和池级奖励计划尚未接入时，边界 Prepare 会明确失败并保持上一 durable 状态，避免漏结算后继续出块或未来重复补发。

新增 `crates/bit-staking`，实现 D-007 第一阶段的验证者、池、持仓和激活容量账本。validator_id/position_id 统一复用 `bit-types` 的链上下文域；普通委托和 self-bond 分别执行 1 BIT、1000 BIT 的参考测试网最低值。Pending 固定到下一 epoch，不计旧周期奖励；每激活 epoch 最多接受 1000 个，未处理前取消会释放容量。

份额和池价值计算使用 U256 中间乘法并 checked 转回 Amount。bootstrap 池按本金 1:1 铸造份额，此后按 `floor(D*S/P)`；零份额或低于 `min_shares` 不成交并转为可退款。`P=0,S>0` 的旧代池会把已接受 pending 转为可退款，`P>0,S=0` 则作为损坏状态拒绝。销毁最后全部份额时取走全部 P，避免舍入残余永久留池。

epoch 批量激活先处理按 position_id 排序的 self-bond，再处理普通委托，消除本地 map 遍历顺序差异。候选按有效池资产降序、validator_id 字节升序选择前 64 名，投票权按 1 BIT 单位换算并检查 `2^60-1` 安全上限。`bit-emission` 同时补上 Delegate 建仓、激活、取消/退款的 `Q/D/P/F` 原子容器转换。

质押状态已逐项接入 schema v7：参数、validator、pool、position 和 activation-capacity 使用带版本的严格持久化编码及独立 JMT 键。validator v2 持久化公开元数据并拒绝重复 consensus key；恢复收据在交易格式、状态转换和持久化解码三层都严格限定为 512 字节。块内只写触及的记录；Prepare 交叉验证 pool/P、pending/D，Commit 成功后才替换内存账本。

RegisterValidator、Delegate、CancelPending 已完成可从 ABCI 生命周期到 RocksDB 的统一执行链。owner、operator、consensus-pop 使用独立 Ed25519 域并绑定完整 64 字节 effect hash；自质押 operator 从当前验证者记录解析。公开 lock/release 与手续费纳入 Penumbra binding equation。真实 Groth16 集成用例覆盖注册元数据及 PoP、普通委托的 `Q→D`、从 released value 支付费用的 pending 取消、ICS23 证明和重启恢复。

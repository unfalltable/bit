# 14　全量测试、性能与最终完成定义

## 14.1 测试金字塔

数学/类型单元测试；协议 property tests；密码学固定向量与负例；实际多进程共识集成；钱包/节点界面 E2E；网络隐私抓包；平台构建；故障注入；资源性能；外部审查与独立复现。

不能让测试只验证被 mock 的服务返回预设余额。密码学与共识相关 E2E 使用真实 Spend/Output 证明与真实 CometBFT 进程。可以为 UI 布局单独使用 mock，但布局通过不构成功能验收。

## 14.2 必须通过的资金流程

创建并备份钱包 A/B → 创世领取或测试发放 → A 私密支付 B → B 验证到账 → B 创建独立持仓 → 激活 → 节点产生多个真实 epoch → B 离线后恢复发现收益 → 部分退出 → 等待双条件 → 领取并再付给 A → 恢复 B 到新设备 → 找回剩余票据、持仓与退出状态。

第二条：全部余额锁定 → RELEASED_VALUE 承担 Unbond 费用 → 到期继续以释放额承担 Claim 费用 → 可用余额恢复。第三条：验证者公开违规 → 处罚任务完整结算 → 本金/退出池/总供给同步减少 → 未成熟不能抢领 → 剩余权益仍可退出。

## 14.3 密码学与协议负例

错误 Spend proof、错误 Output proof、错误 binding signature、错误公钥/群编码、错误 proof manifest、跨链旧签名、错费用、改收款密文、重复 nullifier、同块两个花费、过期 anchor、超范围 amount、构造非本币正价值、伪造 Claim 正释放、错误持仓主人、旧 sequence、未知业务动作。

每个字段篡改必须覆盖，不能只测试一个“签名错误”例子。原语固定向量在所有正式目标平台一致；任何平台出现不同 envelope/哈希/签名验证结果即阻断。

## 14.4 质押数学属性

所有合法序列保持总供给不变量；存入/退出/领取原子；ceil/floor 边界无套利；最后持仓和最后退出份额不遗留无主余额；pending 不提前赚奖励；离线不造币；处罚不重复；处罚作业中断恢复不重复扣罚；佣金不超过预定比例；更换共识键不清历史证据；所有份额归零或 P=0 状态有确定处理。

参考 Python 模型只验证若干整数关系，是独立 oracle 的起点，不替代 Rust 链实现的 property tests，更不验证零知识证明安全。

## 14.5 共识与故障

4 节点本地网络：逐个停机、重启、消息延迟、网络分区、同一交易重复广播、不同 mempool 顺序、错误提案、重放同一块和验证者更新偏移。超过三分之一权重故障时观察真实停滞，不通过降低阈值使测试“成功”。

64 活跃验证者实验用独立进程与可控网络拓扑，不用 64 个线程冒充独立故障域。此实验也不证明现实权重已经独立控制。

## 14.6 钱包与 UI

覆盖全部 W01–W41、N01–N16、E01–E08，含移动/桌面尺寸、中文/英文、深浅主题、200% 字体、断网、权限拒绝、锁定、磁盘不足与恢复。每个资金页面至少一个真实链 E2E。

无 FaceID/指纹调用、无短信/手机号/邮箱注册、无广告追踪。后台/锁屏按规定清空解锁能力，未授权不能执行旧 plan；用户改密码中途断电仍可恢复。

## 14.7 隐私测试

在受控网关、DNS 和模拟故障环境抓取钱包所有出站连接。privacy_required 模式下 Tor 失败应零钱包链直连；外部服务器不能收到 seed/查看密钥/持仓根/通讯录。错误日志、崩溃包与诊断导出逐项扫描。

用公开链数据验证普通支付没有明文收付地址/金额；同时明确证明质押 position/金额/时间可公开关联，测试不能把这部分泄漏误报为“已经全部隐藏”。

## 14.8 性能目标（必须报告实测，不伪造）

| 场景 | 目标与记录 |
|---|---|
| 家庭基准 | 四核、8/16GB、512GB SSD、10Mbps 上行，明确机器型号与系统 |
| 普通手机 | 本地单笔典型支付证明耗时 p50/p95、峰值 RSS、耗电和发热 |
| 提交到验证到账 | 健康网络、实际 Tor 链路下 p50/p95，目标 p95 ≤30秒；包含头/状态验证 |
| 证明构造 | 典型 2输入2输出目标 p95 ≤10秒；失败不以服务器代签/假证明通过 |
| 节点负载 | 低负载7日稳定、目标20TPS压力及无效证明攻击；记录失败阈值 |
| 手机同步 | 以实测 compact bytes/tx 计算日流量；常用账户 24h 数据补扫目标≤60秒，给出测试真实负载 |
| 钱包恢复 | 用1年、不同交易量历史数据，报告流量、时长、失败与续扫能力，不承诺固定值 |
| 数据增长 | 当前状态、nullifier、历史数据的 GB/月；不能仅报初始空链大小 |

如果目标没有达到，诚实记录并优化，或将正式运行 profile 的吞吐上限调低；不能把失败报告删掉。产品仍是全功能正式规格，不因容量保守变成 MVP。资金安全与匿名性不得以性能理由被悄悄降级。

## 14.9 最终完成定义

所有需求有对应实现路径与测试 ID；所有正式平台构建与安装/卸载测试；所有核心流程在真实多节点测试网络运行；API/CLI/页面无不可达空按钮；无核心 TODO/unimplemented/mock verifier；恢复、升级、断电与处罚演练有结果；依赖和参数已锁定；文档与实际行为一致。

面向真实资产的 release 还要求独立审查、剩余风险披露、真实主网创世签署、网络参与者和服务基础设施准备就绪。自动化工具可以验证证据文件存在和哈希，但不能替人凭空出具审计结论或独立运营事实。

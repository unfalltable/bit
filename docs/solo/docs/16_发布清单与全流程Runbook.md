# 16　发布清单、操作手册与交付验收

## 16.1 开发者完整启动手册

克隆代码并校验 release/source hash → 安装锁定工具链 → `just bootstrap` → `just test-all` 的可用平台测试 → `just localnet` → CLI 领取测试资金 → 启动钱包 → 完成付款、质押、退出与恢复 → 浏览器验证公开状态 → 停止一个节点并验证容错 → 导出测试报告。

首次构建实际需要下载上游源码/参数和系统依赖；README 要逐项写明，不声称压缩包无需网络即可直接变成全套 App。证明参数下载经过固定 hash 校验，不能运行未知远端 shell 脚本。

## 16.2 家庭用户安装手册

验证安装包 → 安装节点管理器 → 设备与网络诊断 → 选择数据路径 → 核验网络与快照 → 同步完成 → 创建独立共识身份 → 用手机授权注册/自质押 → 等待候选规则生效 → 查看真实活跃与奖励状态。

卸载前展示数据与签名状态的备份区别。节点停止不代表资产退出；必须在钱包签署解除质押并等待。重新安装不得自动生成新身份却继续显示旧奖励。

## 16.3 主网创世仪式

冻结经济与资源参数，确定真实参与者公钥与份额 → 独立验证创世领取权和初始自质押不重复 → 检查初始权重集中情况 → 校验依赖、参数、各平台 release hash → 多方核对并签署 manifest → 运营者各自配置节点 → 钱包绑定唯一 genesis hash → 公布启动信息与明确风险 → 观察真实共识运行。

基于独立公钥并不能证明独立自然人，本版不做实名系统。运营独立性说明需要真实组织/个人自愿提供和核查，不能通过“创建64个名字”生成。

## 16.4 首次真实资产发布前核对

代码、数据库、参数、manifest、安装包和文档版本完全一致；没有测试种子；初始供给校验；验证者历史与 operator key 可恢复；至少有独立服务来源；检查点信任流程可用；安全审查关键问题关闭；故障恢复演练记录；适用地区商业化与发行条件经专业评估；平台分发具备真实签名和许可。

此处不提供特定司法辖区的法律结论。无实名或隐私设计不自动排除虚拟资产、支付、发行、交易或软件分发方面的法律义务。不得让 Codex 因“不收集身份”就自动判定合规。

## 16.5 交付目录验收

完整源码、依赖锁、crypto manifest、所有核心测试向量、全部安装包/可复现构建说明、gateway/openapi、节点/钱包 CLI、部署文件、用户手册、节点迁移手册、威胁模型、独立审查范围、实际测试报告和 known issues。

`release_manifest.json` 包含 artifact hashes、协议兼容、签名者 public keys、签名、mainnet_ready 和阻断项。mainnet_ready 不是代码默认 true；由 preflight 对真实证据检查后生成并由真实发布者审阅。

## 16.6 完整范围的结束条件

开发完成定义是功能与证据闭环，而不是“主页可打开”。所有 W/N/E 页面有真实行为与异常状态，所有 PR 需求能定位代码及测试，全部资金动作与供给不变量相符。真实资产上线再满足其额外门槛。

这份规格允许编程工具持续实施全套系统，但没有任何文档或单次提示能合理保证无漏洞。禁止将“AI 生成”或“无智能合约”用作无需独立验收的理由。

# 02　系统架构、技术栈与代码仓库

## 2.1 进程与信任边界

```text
Flutter 钱包界面
  │ 仅调用本地类型化 FFI；不持有长期明文种子
Rust wallet-core ── 本地加密 vault / 扫描数据库 / 轻客户端
  │
Arti 钱包网络层 ── 多个独立 sync gateway / broadcast gateway
                              │ 公共数据，无用户资金权限
                         Solo RPC / indexer
                              │
CometBFT P2P+共识 ── ABCI ── Rust solo-app ── JMT/RocksDB
             │                   │
    本机 durable signer      确定性账本 / 质押 / 费用 / 发行

Flutter 节点管理器 ── OS 本地 IPC ── solo-node-agent
                                            │
                           应用、CometBFT、signer 子进程

只读浏览器 ── public gateway ── PostgreSQL 索引
```

Rust wallet-core 是签名、金额运算、证明生成和本地隐私状态的唯一实现；Flutter 不重新实现密钥派生和资产计算。公开查询可以缓存，但资产权威来自验证后的链状态。

## 2.2 技术栈锁定

| 范围 | 选型 | 锁定与理由 |
|---|---|---|
| 核心语言 | Rust，项目 edition 2021 | 编译器参考 1.98.1；须实测完整依赖兼容，不称已编译通过 |
| 共识进程 | CometBFT 0.38.23 | 发布构建前查官方安全通告；记录源码 SHA 与镜像 digest |
| Rust ABCI | tendermint-abci/proto 0.40.4 的 v0_38 方言 | 显式实现 FinalizeBlock 等，不使用旧 DeliverTx 生命周期 |
| 密码学组件基准 | Penumbra v2.1.1 的选定源码与 Cargo.lock | 固定 Spend/Output、电路和参数的内容哈希，不启用其 app |
| 状态存储 | cnidarium/JMT/RocksDB 上游兼容组合 | 原子提交、状态证明、快照与重放 |
| 服务端异步 | Tokio、Tonic、Axum | 从审查后的兼容依赖集锁版本，不写浮动 latest |
| 钱包 UI | Flutter stable | 参考 3.47.2；移动与桌面共用组件，平台差异显式测试 |
| Rust/Flutter | flutter_rust_bridge 2.x | Dart 包、Rust crate、codegen 使用匹配精确版本 |
| 钱包 DB | SQLite + SQLCipher | SQLCipher 确实参与加密，不能仅给明文 SQLite 加密码字段 |
| 密钥库 | Argon2id + XChaCha20-Poly1305 | 随机独立数据密钥，密码派生密钥只用于包裹 |
| 钱包网络 | Arti/arti-client | 所有钱包链流量由 Rust 统一接管，不让 Flutter HTTP 绕过 |
| 索引数据库 | PostgreSQL 17 兼容线 | 部署冻结时选受维护补丁版；金额 NUMERIC(37,0)，并额外检查 <2^120 |
| 只读浏览器 | React + TypeScript + Vite | 无签名/助记词页面，静态资源自托管，不载第三方分析 |
| 可观测性 | Prometheus + Grafana + 结构化日志 | 仅节点与服务指标，无用户资产标签 |
| 测试 | Rust unit/proptest/cargo-fuzz、Flutter integration、Playwright | 加真实多进程共识及故障注入 |
| 打包 | Docker Compose、systemd、原生安装包 | 家用运行不要求 Kubernetes；不强制 Docker 才能用钱包 |

这些版本是可追溯的参考基线，不是已完成的整栈兼容性报告。D-001 必须生成 `dependency-lock.json`、SBOM 与平台构建结果；兼容升级需要 ADR、重复测试，不能为绕过失败改用停止维护的组件。[S03][S06][S07][S08][S09][S10]

## 2.3 平台矩阵

钱包必须覆盖 Android arm64、iOS arm64、Windows x64、macOS arm64/x64、Linux x64。移动端最低系统版本以锁定 Flutter 与 Rust 依赖的共同支持范围为准，在 D-001 固定 `platform-support.json`，不能把未实测的系统写为支持。

节点正式支持 Linux x64/arm64 和 macOS arm64/x64。Windows 家庭用户提供图形化 WSL2 管理模式：检测或引导启用 WSL2，节点在受管理的 Linux 环境运行；明确首次启用可能需要系统权限与重启，不宣称纯原生免配置。钱包自身在 Windows 原生运行。发行版本须把 WSL2 的备份、磁盘、休眠和网络变化纳入测试。

## 2.5 组件接口与禁止耦合

`solo-app` 只能依赖纯确定性规则与状态仓库，不能调用互联网、索引 DB、墙上时钟、随机数或本机配置决定交易结果。证明验证可并行，但最终应用按区块顺序确定。

`solo-wallet-core` 负责私钥；`solo-gateway` 不得依赖 custody/key-export 模块。`solo-node-agent` 不得提供通用钱包签名接口。浏览器不嵌入钱包管理，不导入恢复词。

密码学适配层必须限制在本链用到的原语与动作，保留上游许可证。删除 action 路由同时删除功能可达性；不能因 transitive dependency 含某类型，就让 DEX/IBC 动作通过反序列化和执行。

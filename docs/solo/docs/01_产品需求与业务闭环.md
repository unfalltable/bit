# 01　产品需求与端到端业务闭环

## 1.1 用户与权限

普通持币者拥有钱包资金；委托者拥有每个持仓的控制密钥；验证者运营者拥有离线操作密钥与独立在线共识密钥；查询服务仅持有公开链数据；项目维护者负责发布源代码和签名软件，不拥有用户余额的后台修改权。

所有资产权限由本地密钥与链上规则控制。服务器“登录成功”不构成资金权限。业务层没有超级管理员、钱包冻结或管理员重设助记词接口。

## 1.3 创建与首次入金

打开应用，明确提示“本地非托管钱包，无平台账号”。创建随机种子，设置本地密码，展示并确认恢复凭证，验证备份完成后进入首页。可先查看钱包，但对外展示接收重要资产前必须完成备份确认；不把“跳过备份”作为默认顺滑路径。

初始资金来自已有持币者转账或公开创世分配。钱包不承诺匿名空地址免费获得主网币。测试水龙头只存在于测试网，界面必须有常驻测试网标识，且不可兑换主网资产。

## 1.4 支付闭环

收款人本地生成新收款地址与二维码；付款人解析、校验链与金额，在本地确认并生成证明与签名；广播后先显示待确认；接收端下载通用 compact blocks，本地解密匹配、验证票据承诺与区块状态后显示到账。

失联时保留待定状态，不重新签署一笔相同金额付款。恢复连接后先查原交易及其 nullifier 状态，再决定重播或重建。截图、商家后台的 HTTP 200、广播接口返回哈希，都不等于结算。

## 1.5 商家收款、对账与退款

支持本地创建带金额、随机 invoice_id 和有效期的收款请求。invoice_id 与订单备注只进入加密 memo，不放到公开链字段。商家端同样由本地钱包扫描对账；不可把完整查看密钥交给公共网关。

发票过期不等于链拒绝普通转账；迟到、少付、多付、重复付款应分别显示，不能吞币。退款是一笔新转账，需核对收款方提供的地址和实际金额，由商家本地确认签名。无客服撤销已确认交易、无系统默认拒付。

## 1.6 质押与收益闭环

选择验证者，显示公开佣金、状态、退出等待、关联风险与处罚规则。输入金额，自动保留可用手续费；签名后生成独立持仓，先为 pending，下一周期激活。只有进入实际活跃验证集合并符合奖励条件的权益才获得相应奖励。

奖励增加池中原生币资产，不增加用户份额数量，用户的份额对应价值上升。没有领取按钮作为每日任务；累计收益可能受罚没影响，显示净变动及独立的奖励/罚没分项，不保证数值一直为正。

## 1.7 退出闭环

用户按份额或“全部”退出。链计算当前可退出价值，扣除明示手续费，生成不可转移退出票据。冻结期间不参与奖励，仍在明确证据范围内承担处罚。到期必须同时满足高度与链上时间条件，并完成有关处罚任务。

到期不是服务端定时器自动加钱：钱包在用户已解锁且有确认的情况下签署 ClaimExit，将成熟权益转换成新私密票据；可一次确认有限数量的领取。用户离线不丢失领取权，不强制让后台保存签名密钥。文案用“可取回”，不能提前计入可用余额。

## 1.8 验证者闭环

桌面端安装节点，检测设备、网络、时钟和磁盘，生成共识密钥与防重复签名数据库。手机扫描节点请求，确认本链、节点指纹、佣金等，签署注册与自质押。候选与活跃状态清晰区分。退出时先停止参与并完成链上解绑，再迁移或销毁在线密钥；不能把同步目录打包给别人后两处同时开机。

奖励只能由合法质押与验证规则产生，绝不按软件打开时长、IP 数量或“矿机等级”发放。

## 1.9 恢复闭环

恢复凭证重建 wallet root，再派生支付密钥、持仓根密钥与查看能力。全链 compact 数据扫描恢复所有支付票据与加密持仓收据；不依赖已丢失设备上的索引计数。联系人与本地订单标签需独立加密备份，不能承诺仅靠助记词恢复从未上链的备注。

恢复验证者资金钱包不恢复可安全在线签名的共识状态；必须单独执行节点密钥迁移流程。

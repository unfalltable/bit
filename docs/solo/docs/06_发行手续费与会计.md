# 06　发行、手续费、奖励与全局会计

## 6.1 参考经济配置

开发参考：8 位小数；创世总额 100,000,000 SLC；名义发行率每目标年 2%；目标块间隔 5 秒；每 epoch 720 块。**这是工程默认，不是用户已批准的主网经济政策，也不是保证年化收益。**主网不得偷偷采用测试分配或团队份额。

不写死 BTC 式 2100 万上限。当前采用持续协议发行，不设置任意管理员 mint。若主网决定固定上限，必须同时冻结发行曲线及长期安全预算，并更新数学模型与验收，不能只改首页显示总量。

## 6.2 总量会计

定义全都以最小单位记录的非负整数：

- Q：私密池总资产（公开边界余额，不是每个人的余额）；
- P：所有活跃/非活跃质押池持有的本金与已计入收益；
- D：待激活/可退款的委托本金；
- X：所有退出 cohort 的剩余资产，包括成熟未领取；
- C：验证者佣金应付余额；
- F：待分配手续费及整数余量储备；
- G：未领取的创世分配；
- T：流通与锁定之和，即当前存量。

```text
T = Q + sum(P) + D + sum(X) + sum(C) + F + G
T = genesis_supply + cumulative_minted - cumulative_burned
```

没有公开个人余额仍然可以维护 Q 的总资产账：公开的存入、取出、费用与发行对边界总额的影响是可知的，私密池内部转账不改变 Q。不得用全量解密来做账目检查。

## 6.3 发行算法

每个 epoch 完结一次结算。设 `Y=6,307,200`（365 天、每目标块 5 秒）、`L=720`、`bps=200`、`denom=10000*Y`。

```text
n = epoch_start_supply * bps * L + emission_carry
scheduled = floor(n / denom)
new_carry = n % denom
```

`epoch_start_supply` 是该 epoch 首块前确定的存量快照。名义年率依赖实际出块速度；停链时不凭墙上时钟补发“离线收益”。屏幕显示“协议名义发行率”，不能直接当作用户 APY。

按上一 epoch 实际共识参与计算 `score_v = sum(actual_voting_power_on_signed_blocks)`，缺席不加分。协议给每个有分数且剩余池 P>0 的合格验证者分配奖励。若 total_score=0 或无合格池，本期不铸币，carry 按预定余数更新，不累积未来可补领的整数“欠币”。

先执行 `minted=min(scheduled, technical_supply_cap-current_supply)`；达到技术上限后 minted=0，不结转被上限截断的整数发行。后续所有分配公式使用 minted 而不是未截断的 scheduled。`distributable = minted + old_fee_reserve`。各验证者按 `floor(distributable * score_v / total_score)` 获得毛额，整数余量保留 F；实际铸币 minted 计入 T。每池毛额按佣金 bps 拆为 C 与 P。不存在项目方社区池抽成，除非后续公开改变经济规则；本版无此入口。

被 tombstone/正在处罚或没有活跃权益的池不获得本期分配；必须在计算 total_score 前按同样资格过滤，避免分母包含不可付对象而造成账目悬空。自质押不足的验证者仍按实际有效块历史判断其既有权益，本期是否被排除由其结算时的安全状态决定，规则统一。

## 6.4 金额、精度与安全边界

Amount、Shares 使用 U128，外部金额限制 `<2^120`；乘除中间使用 U256，所有溢出拒绝。比例 bps 为 0..10000。JSON 用字符串，PostgreSQL 用 NUMERIC，Dart 与 JS 不将金额解析为 double/Number。

此外，供给到投票权的转换必须受 int64 限制：工程经济参数设置 `max_voting_power = 2^60-1`，mainnet manifest 的技术供给上界除以固定 power_unit 必须不超此上限。创世校验必须拒绝无法满足此条件的组合。系统不能声称无限增发却永远不检查边界；接近可表示/可投票上界时在预定高度停止额外发行，并显示协议技术上界，不能回绕或隐式改单位。

份额存入向下取整，最后全池退出取全部 P；cohort 领取同理。向下舍入的剩余仍在相同资产容器内，不转给维护者。重复拆单不得凭空获利，参考模型与属性测试覆盖分拆、合并、极小金额及全退出。

## 6.5 手续费规则

Fee 只接受本币，金额公开。手续费是阻止资源滥用的一部分，不保证能抵御一切垃圾流量。普通用户不需要选择 gas token。

参考最低费（原子单位）：

```text
base = 1_000
per_kib = 200
per_spend_proof = 500
per_output_proof = 500
new_position_surcharge = 100_000
validator_registration_surcharge = 100_000_000
min_fee = base + ceil(canonical_tx_bytes/1024)*per_kib
        + spend_count*per_spend_proof + output_count*per_output_proof
        + applicable_surcharge
```

手续费编码占固定长度，不因十进制字长改变资源模型。钱包构造完整交易后复核实际大小；若低于最低费则重新计划并再次呈现变化，不偷偷提高已确认费用。手续费不是法币定价，币价未知时不能宣传人民币几分钱。

区块资源拥堵以可审查报价和有上限的加费处理，本版不做复杂 fee market。有效但没进块的交易未扣款。已入块业务失败的原子交易本版不扣费；DoS 防护主要由提案拒绝无效交易、mempool 限额和前置验证承担，必须实测攻击负载。

## 6.6 避免“全部质押后无法付费”

钱包 Delegate 默认保留近期若干操作的费预算，并清楚区分可用与质押余额。即便用户使用其他客户端把可用余额全部锁定，Unbond 与 ClaimExit 支持从合法退出价值中支付费，CancelPending 与 ClaimCommission/Genesis 也可从释放额承担费。

若合法释放额不够最小费用，使用额外私密输入补足；钱包提示需要补充极少本币，不提供假的免费链上交易。第三方可以正常向该用户转入本币，但本版本没有无限代付或任意代操作授权。

## 6.7 创世闭环

主网创世条目采用公开领取权：claim_id、claim_pubkey、amount、可选公开锁定规则（本版不支持自定义释放脚本）、分配说明和独立审批签名。未领取部分记 G，领取需该 key 对完整交易签名，金额从 G 释放到私密 Output；领取一次即消耗。

初始验证者自质押直接记入明确的 genesis positions，计入 P，不在 G 重复计算。创世校验要求 `G+P+其他明确创世容器=genesis_supply`。不允许拿同一份币同时做创世收款和自质押。

测试脚本可用固定、公开、带巨大警告的测试种子；主网不能使用这些种子。真实领取者与运营者应各自生成私钥，只提供公钥和签名。维护者不能替他们持有主网私钥。

## 6.8 金额例子

一个池 P=1,000，S=1,000；用户投入 100，铸 100 份，池变 1,100/1,100。收到毛奖励 11，佣金 5%=0.55，P 增加 10.45，C 增加 0.55。该用户持仓价值为 100*1,110.45/1,100=100.95。

若全退出该用户的 100 份，扣明示费用后转成退出权益；不是系统重新凭空铸造 100.95。罚没减少 P/X 和 T；支付普通手续费只在 Q 与 F 间转移，不减少 T。参考程序仅用于验证这些整数会计关系，不是链实现或密码学测试。

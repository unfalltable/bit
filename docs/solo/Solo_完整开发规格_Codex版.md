# 00　总则、交付范围与已冻结决策

文档版本：1.0。编制日期：2026-09-07。工程代号：**Solo**；测试币显示符号 **SLC**，最小单位 **uslc**。这些名字仅是工程占位，不代表品牌核准、现实中的同名项目或主网发行决定。

## 0.1 本文档的性质

这是完整产品的开发规格与验收合同，不是精简演示版，也不是已经写好或已经通过审计的公链软件。钱包、节点、账本、质押、恢复、索引、浏览器、部署、升级、测试均在同一正式交付范围内。分任务顺序只用于组织实施，不代表先上线一个删减版本。

Codex 应据此产生真实可运行代码、迁移、构建产物与测试证据。不能用假余额、定时器奖励、单机数据库模拟共识、返回 true 的证明验证、隐藏按钮的方式冒充完成。不能把文档存在、编译成功或测试网络出块，等同于真实资产环境已经安全。

参考资料以 `[Sxx]` 编号出现在相应事实之后；完整地址和核验日期在 `docs/19_参考资料.md`。本文自主设计的接口、参数、公式、页面和验收门槛属于**项目设计决策**，不是上游项目已实现或已测出的能力。

## 0.2 不可变的用户要求

独立原生链；只有一种可流通原生币；普通支付与质押；不依赖另一条链运行；不开放通用智能合约；不要求专用矿机、独立显卡；家用电脑可申请成为验证者；手机可非托管委托质押；无需实名、手机号、邮箱；不用指纹或面容；本地密码与恢复备份；日常扫码操作简单。

“不依赖其他链”允许复用开源软件和密码学实现，不允许把安全性、资产或结算交给另一条链。“匿名”定义为下节的具体隐私属性，不宣传绝对不可追踪。“低门槛”指操作与硬件，不代表不需要初始币、不需要联网或所有节点都有活跃席位。

## 0.4 为什么细化为“独立公钥持仓”

先前方案已经允许质押金额、验证者与时点公开。本规格进一步明确：每次创建持仓生成一个独立控制公钥，链上能追踪此持仓的变更，但没有用户姓名、手机号、支付地址或钱包总余额字段。不要把它称为“所有质押活动完全隐藏”。

这个选择避免为了“不让质押凭证交易”临时发明新零知识电路，也避免偷偷生成可流通质押衍生币。正常支付保持隐私。持仓并非法律意义的实名账户；公钥和位置标识只表示链上权限。把一把私钥卖给别人无法从协议层彻底阻止，因此“不可转移”准确指**协议没有转移持仓所有权的交易类型**。

如果今后要求每一笔质押金额及不同阶段关联也隐藏，那是隐私保证的升级，必须另立协议版本和密码学审查，不能在本规格中假装已经提供。

## 0.5 公开与隐藏边界

| 数据 | 对普通链观察者 |
|---|---|
| 普通支付金额、收款地址、输入对应的旧票据 | 默认不公开；付款人与收款人有各自所需信息 |
| 交易时间、大小、输入/输出个数、手续费、业务类型 | 可观察；它们仍可能构成关联线索 |
| 质押/退出金额、验证者、持仓公钥、position_id | 公开；同一持仓的生命周期可关联 |
| 钱包总资产、姓名、手机号、邮箱、通讯录 | 协议无此公开记录；本产品不采集身份信息 |
| 验证者共识公钥、投票权、公开佣金、证据 | 公开；独立运营者现实身份不由协议强制登记 |
| IP 与连接时序 | 钱包尽量经 Tor 保护；不承诺抵抗全球流量关联，也不承诺验证者网络位置匿名 |
| 订单对手方掌握的现实身份信息 | 本链无法消除 |

已有隐私系统也区分支付隐私、委托公开信息与网络元数据；不能把“不注册”替代密码学隐私。[S04][S05]

## 0.6 全量功能与明确排除

必须交付：多平台钱包、桌面节点管理器、节点守护进程、CLI、原生质押与奖励、隐私同步网关、可验证索引接口、只读浏览器、恢复与备份、签名发布流程、故障演练、完整文档与回归测试。

明确排除：EVM、WASM/CosmWasm、任意用户程序、其他资产发行、IBC/跨链桥、NFT、借贷、DEX、法币兑换、托管平台账户、第三方资金授权、身份认证、手机/邮件注册、广告与追踪、邀请返利、矿机等级、保证收益。

交易平台接入仅提供原生充提所需的 CLI/SDK 与只读证明接口；不内置交易平台，不承诺市场流动性。适用地区审查、商店签名证书和真实创世名单是上线外部输入，不由模型编造。

## 0.7 规格优先级

资金守恒与权限规则 > 密码学原始规范和固定测试向量 > 本项目协议与状态机 > 接口合同 > 页面规格 > 示例配置。发现冲突必须写 ADR（架构决策记录）、补一致性测试再修改；不能只改界面文案掩盖。

默认以本包参数开发完整 localnet/testnet；主网需签署 genesis 与 release manifest。没有真实运营者、公钥、审计证据时，主网启动器应明确拒绝，不得用示例私钥或自动生成的“已批准”记录绕过。

# 01　产品需求与端到端业务闭环

## 1.1 用户与权限

普通持币者拥有钱包资金；委托者拥有每个持仓的控制密钥；验证者运营者拥有离线操作密钥与独立在线共识密钥；查询服务仅持有公开链数据；项目维护者负责发布源代码和签名软件，不拥有用户余额的后台修改权。

所有资产权限由本地密钥与链上规则控制。服务器“登录成功”不构成资金权限。业务层没有超级管理员、钱包冻结或管理员重设助记词接口。

## 1.3 创建与首次入金

打开应用，明确提示“本地非托管钱包，无平台账号”。创建随机种子，设置本地密码，展示并确认恢复凭证，验证备份完成后进入首页。可先查看钱包，但对外展示接收重要资产前必须完成备份确认；不把“跳过备份”作为默认顺滑路径。

初始资金来自已有持币者转账或公开创世分配。钱包不承诺匿名空地址免费获得主网币。测试水龙头只存在于测试网，界面必须有常驻测试网标识，且不可兑换主网资产。

## 1.4 支付闭环

收款人本地生成新收款地址与二维码；付款人解析、校验链与金额，在本地确认并生成证明与签名；广播后先显示待确认；接收端下载通用 compact blocks，本地解密匹配、验证票据承诺与区块状态后显示到账。

失联时保留待定状态，不重新签署一笔相同金额付款。恢复连接后先查原交易及其 nullifier 状态，再决定重播或重建。截图、商家后台的 HTTP 200、广播接口返回哈希，都不等于结算。

## 1.5 商家收款、对账与退款

支持本地创建带金额、随机 invoice_id 和有效期的收款请求。invoice_id 与订单备注只进入加密 memo，不放到公开链字段。商家端同样由本地钱包扫描对账；不可把完整查看密钥交给公共网关。

发票过期不等于链拒绝普通转账；迟到、少付、多付、重复付款应分别显示，不能吞币。退款是一笔新转账，需核对收款方提供的地址和实际金额，由商家本地确认签名。无客服撤销已确认交易、无系统默认拒付。

## 1.6 质押与收益闭环

选择验证者，显示公开佣金、状态、退出等待、关联风险与处罚规则。输入金额，自动保留可用手续费；签名后生成独立持仓，先为 pending，下一周期激活。只有进入实际活跃验证集合并符合奖励条件的权益才获得相应奖励。

奖励增加池中原生币资产，不增加用户份额数量，用户的份额对应价值上升。没有领取按钮作为每日任务；累计收益可能受罚没影响，显示净变动及独立的奖励/罚没分项，不保证数值一直为正。

## 1.7 退出闭环

用户按份额或“全部”退出。链计算当前可退出价值，扣除明示手续费，生成不可转移退出票据。冻结期间不参与奖励，仍在明确证据范围内承担处罚。到期必须同时满足高度与链上时间条件，并完成有关处罚任务。

到期不是服务端定时器自动加钱：钱包在用户已解锁且有确认的情况下签署 ClaimExit，将成熟权益转换成新私密票据；可一次确认有限数量的领取。用户离线不丢失领取权，不强制让后台保存签名密钥。文案用“可取回”，不能提前计入可用余额。

## 1.8 验证者闭环

桌面端安装节点，检测设备、网络、时钟和磁盘，生成共识密钥与防重复签名数据库。手机扫描节点请求，确认本链、节点指纹、佣金等，签署注册与自质押。候选与活跃状态清晰区分。退出时先停止参与并完成链上解绑，再迁移或销毁在线密钥；不能把同步目录打包给别人后两处同时开机。

奖励只能由合法质押与验证规则产生，绝不按软件打开时长、IP 数量或“矿机等级”发放。

## 1.9 恢复闭环

恢复凭证重建 wallet root，再派生支付密钥、持仓根密钥与查看能力。全链 compact 数据扫描恢复所有支付票据与加密持仓收据；不依赖已丢失设备上的索引计数。联系人与本地订单标签需独立加密备份，不能承诺仅靠助记词恢复从未上链的备注。

恢复验证者资金钱包不恢复可安全在线签名的共识状态；必须单独执行节点密钥迁移流程。

# 02　系统架构、技术栈与代码仓库

## 2.1 进程与信任边界

```text
Flutter 钱包界面
  │ 仅调用本地类型化 FFI；不持有长期明文种子
Rust wallet-core ── 本地加密 vault / 扫描数据库 / 轻客户端
  │
Arti 钱包网络层 ── 多个独立 sync gateway / broadcast gateway
                              │ 公共数据，无用户资金权限
                         Solo RPC / indexer
                              │
CometBFT P2P+共识 ── ABCI ── Rust solo-app ── JMT/RocksDB
             │                   │
    本机 durable signer      确定性账本 / 质押 / 费用 / 发行

Flutter 节点管理器 ── OS 本地 IPC ── solo-node-agent
                                            │
                           应用、CometBFT、signer 子进程

只读浏览器 ── public gateway ── PostgreSQL 索引
```

Rust wallet-core 是签名、金额运算、证明生成和本地隐私状态的唯一实现；Flutter 不重新实现密钥派生和资产计算。公开查询可以缓存，但资产权威来自验证后的链状态。

## 2.2 技术栈锁定

| 范围 | 选型 | 锁定与理由 |
|---|---|---|
| 核心语言 | Rust，项目 edition 2021 | 编译器参考 1.98.1；须实测完整依赖兼容，不称已编译通过 |
| 共识进程 | CometBFT 0.38.23 | 发布构建前查官方安全通告；记录源码 SHA 与镜像 digest |
| Rust ABCI | tendermint-abci/proto 0.40.4 的 v0_38 方言 | 显式实现 FinalizeBlock 等，不使用旧 DeliverTx 生命周期 |
| 密码学组件基准 | Penumbra v2.1.1 的选定源码与 Cargo.lock | 固定 Spend/Output、电路和参数的内容哈希，不启用其 app |
| 状态存储 | cnidarium/JMT/RocksDB 上游兼容组合 | 原子提交、状态证明、快照与重放 |

# 03　密码学、单币约束与交易格式

## 3.1 复用边界：不重新发明证明系统

保留选定上游版本的 BLS12-377/Groth16、decaf377、票据加密、Spend/Output 证明、票据承诺树与随机化花费授权；保留其原始字段约束与基点生成。项目不重新写椭圆曲线运算、群编码、零知识证明算法。[S11]

**质押是新的普通原生状态模块，不是新零知识电路。**公开质押金额通过经过授权的业务动作贡献正或负原生币价值余额，再使用原有交易绑定签名组合。上游交易模型本身区分动作局部证明和全局价值守恒；本项目需为新增动作重新审查会计与签名绑定，不能直接继承上游审计结论。[S12]

## 3.2 必须冻结的密码学清单

`crypto/manifest.json` 至少记录上游仓库、完整 commit、许可证、Spend/Output R1CS 摘要、验证密钥/证明密钥哈希、参数获取来源与设置仪式证明、笔记编码版本、树结构与层数、群/域标识、哈希域、密钥派生路径、地址 HRP、golden vectors 来源。

只在**约束矩阵、公共输入顺序和编码完全不变**时复用原参数。更改电路、曲线或约束必须重新获得与新电路匹配的参数与安全审查；Groth16 不能随意拿旧参数验证新电路。开发时也不能把一次本地可信设置当成正式参数。[S13]

每个证明都检查规范域元素、群成员、子群和长度，遵循原库的安全验证接口；不使用 unchecked 反序列化。校验失败必须拒绝，无远端验证“兜底”。

## 3.3 普通票据与支付

票据正文、承诺、nullifier 派生、随机化地址与接收加密采用固定上游实现。钱包余额只来自本地解密且已验证的未花费票据。节点只维护承诺树、nullifier 集合与协议必要公开状态，不维护明文个人余额表。

典型支付为若干 Spend + 两个 Output（收款、找零），但禁止为了凑固定形状引入未审查的假票据。默认每笔最多 8 个 Spend、8 个 Output、1 个业务动作。金额不足或输入碎片超过上限时，钱包引导进行明确可见的自转合并，再付款；合并同样是真实隐私交易和收费交易。

默认不使用 FMD 把个人过滤密钥交给服务器，而是下载通用 compact 数据并本地识别。各客户端流量与交易形状仍可关联，不承诺强匿名集合的最低规模。

## 3.4 单一资产如何在隐藏金额下成立

主网只定义一个 `native_asset_id`，且创世、奖励、退出、佣金领取只引入这种资产，没有发行其他资产、跨链存入或任意资产转换入口。Spend/Output 使用上游多资产承诺原语，但业务路由只有单币。

不能声称节点可以从加密 Output 直接读到资产 ID。单币非零价值约束来自：原始合法资金仅为本币、每种资产独立的绑定守恒、所有公开释放动作限定本币、无其他资产的合法正余额来源。允许存在无经济价值的零值编码不等于发行第二种有价值的币；必须测试构造非本币正输出无法通过守恒与授权。

不得改用一个“总数守恒”代替按原始资产生成元的价值平衡。若选定上游原语无法证明上述闭包性质，D-003 应阻断合并并提交形式化差异审查，而不是静默弱化。

## 3.5 公开动作与权限

| action | 权限 | 私密池以外的价值变化 |
|---|---|---|
| Transfer | 每个 Spend 的花费授权 | 无；手续费转入费用池 |
| Delegate | Spend 授权 + 新持仓控制公钥的所有权证明 | 原生币从交易价值池进入 pending 持仓 |
| CancelPending | 对应持仓控制签名 | pending 本金释放回交易，可支付手续费 |
| Unbond | 持仓控制签名与序号 | 活跃池减值，退出池增值；选择扣手续费时释放这部分值 |
| ClaimExit | 退出票据所属持仓控制签名 | 成熟退出价值释放入交易，再形成私密 Output |
| RegisterValidator | operator 签名 + consensus key PoP | 支付注册费；自质押由单独持仓绑定 |
| UpdateValidator | operator 签名及 sequence | 元数据、佣金延迟变更、禁用申请；不能挪用户资产 |
| UnjailValidator | operator 签名及资格校验 | 支付费用，无币凭空产生 |
| RotateConsensusKey | operator + 新共识密钥 PoP | 按安全轮换流程改键；历史责任不清除 |
| ClaimCommission | operator 签名及 sequence | 从公开佣金应付账释放本币 |
| ClaimGenesis | 创世条目的 claim key 签名 | 消耗一次性创世领取权并释放本币 |

禁止未知 action、委托凭证转账、任意增发、任意调整本金、运行自带字节码。每笔最多一个业务动作；Transfer 表示没有额外业务动作，而非开放任意调用列表。

## 3.6 价值守恒

以下为规范性会计表达，不可据此自行更换上游群编码：

```text
私密输入之和 + 合法公开释放额
  = 私密输出之和 + 合法公开锁定额 + 手续费
```

绑定验证键由各 Spend/Output 的原生价值承诺，以及公开释放/锁定/手续费的零盲因子承诺组成。所有项使用**同一原语、同一符号约定、同一 effect hash**。公有动作的金额必须由链状态算出或核对，不能接受客户端自行声明一个正释放额。

例：委托 100，支付费 0.01，私密输入 150，私密找零 49.99。池新增 100，而不是运营者钱包收入 100。退出领取 99，扣费 0.01，生成 98.99 的私密输出。重复领取必须在权限和状态层拒绝，即便数学守恒成立。

## 3.7 规范编码与哈希

网络 envelope 使用本项目 Protobuf；签名主体用固定位置的规范 CBOR 数组，不允许浮点、重复键、不定长和任意 map。金额采用 16 字节大端无符号整数，最高 8 位为零，即 `0 <= amount < 2^120`；中间运算至少 U256。JSON 接口只使用十进制字符串。

`canonical_body` 顺序固定：版本、chain_context、expiry_height、anchor、fee、Spend body 列表、Output body 列表、业务动作、证明哈希列表、可空的 528 字节 memo 密文。业务动作内部也是按 action tag 固定字段位置的数组。规范 body 的详细类型与大小由 `contracts/tx_body.cddl` 定义；所有底层 Spend/Output body 字节必须按固定上游规范反序列化再规范编码校验。

```text
chain_context = SHA256("solo/chain/v1" || genesis_manifest_hash)
proof_hash    = SHA256(proof_bytes)
effect_hash   = BLAKE2b-512("solo/effect/v1" || len_u64_be(body) || body)
tx_id         = SHA256(canonical_protobuf_envelope)
```

证明必须先生成并写入其哈希，再签主体；签名列表和 binding signature 不进入自身签名的哈希。花费授权与业务动作授权均绑定相同 effect hash。签名主体包含网络、有效高度、所有公开动作、收款密文和费用，不提供空白授权。

外层 envelope 严格拒绝未知字段、重复 singular/oneof 字段、非规范 varint、超长输入；不能依赖 protobuf 默认“忽略未知字段”来实现共识。提供 Rust/TypeScript/Dart 交叉 golden vectors；只有 Rust 负责编码待签主体，其他端仅用于测试/只读解析。

## 3.8 有效期、重放与异常

有效高度必须满足 `current_height <= expiry_height <= current_height + max_tx_lifetime_blocks`。anchor 必须属于保留窗口内的已提交树根；过期先重新同步再生成。不同 chain_context 的交易全部拒绝。Spend nullifier 在本交易、提案暂存状态和已提交集合均不可重复。

同一合法已广播 envelope 重播返回相同 tx_id，不重新扣款。不能把网络超时直接映射为交易失败。节点拒绝无签名业务动作、错误持仓 sequence、重复退出票据领取和不支持的协议版本。

## 3.9 输入成本约束

先检查字节、字段、数量、过期、签名格式和缓存，再执行昂贵证明验证。区块同时限制 bytes、交易数、Spend/Output 证明数及业务状态写入预算。签名/证明缓存键包含验证版本与完整输入哈希；不得用未验证客户端提供的 tx_id 直接命中可信缓存。

## 3.10 交易级 memo 的固定映射

上游 v2.1.1 memo 是独立交易字段，OutputBody 中包含 wrapped_memo_key；本链 canonical_body 的第10项明确承载原始 528 字节 MemoCiphertext 或 null，参与同一个 effect_hash。沿用原加解密与密钥包装，不把 memo 错塞进不存在的 OutputBody 字段。每笔普通支付默认携带 memo（无文字也用空正文），return_address 使用本次新生成的退款接收地址；同一交易多个输出的接收者都可能读取同一 memo，因此钱包不提供向多个无关收款人发送不同私密备注的批量功能。恢复扫描数据须含该密文。[S23][S24]

本项目在加密前限制用户备注 UTF-8 256字节；发票协议正文用 `solo1:` 前缀加紧凑 JSON，包含 invoice_id 与可选备注，总文本须不超过上游432字节限制，超限拒绝而非截断发票ID。生产解码先检查 ciphertext 恰为528字节，不能依赖上游对短输入补零的宽松转换。无输出时 memo 必须 null；有输出时默认创建真实可解密 memo。[S24]

## 3.11 签名上下文与宽度

本项目 effect_hash 固定64字节（BLAKE2b-512）；chain_context、tx_id、proof_hash仍为32字节。与选定上游 EffectHash 类型做显式适配并用向量验证，禁止把64字节接口随意截断为32字节。Spend/Binding 用原库类型签该 effect；独立 Ed25519 角色使用 `role_domain || effect_hash64`，owner/operator/consensus-PoP/genesis 分别用 `solo/owner/v1`、`solo/operator/v1`、`solo/consensus-pop/v1`、`solo/genesis-claim/v1`。它们共同绑定相同交易效果，但不同角色消息域不同，不让节点 PoP 被误用成共识投票签名。[S23]

# 04　共识、区块执行与状态存储

## 4.1 共识模型

使用权益加权 BFT 验证者集合，不按 IP、电脑台数或地址数量投票。安全假设是恶意投票权严格小于三分之一；出块提交需要超过三分之二投票权，持续出块还依赖网络与在线条件。不能宣传“64 台电脑就足够去中心化”。[S01][S14]

本链不新增 PoW，也不让手机通过保持 App 前台“挖矿”。候选者必须有符合规则的自质押，活跃集合按有效质押选取。普通全节点无出块资格时没有固定开机奖励。

## 4.2 ABCI 2.0 必须实现的调用

| 调用 | 实现责任 |
|---|---|
| Info | 返回最后已提交高度、app hash、协议版本；用于重放握手 |
| InitChain | 严格验证创世、参数、供给、初始验证者与密码学清单 |
| CheckTx | 对已提交快照执行无副作用检查；不能改变最终余额 |
| PrepareProposal | 按资源预算和交易可执行性筛选提案；不得超限 |
| ProcessProposal | 在确定性临时视图中重执行顺序检查，含冲突与预算 |
| FinalizeBlock | 使用同一执行器按区块顺序计算全部状态变化和 app hash |
| Commit | 原子持久化提交，崩溃后可恢复；返回保留高度 |
| Query | 返回指定状态高度的数据和可验证证明 |
| Snapshot 系列 | 分块导出/导入、资源限制、状态根核对 |
| ExtendVote/VerifyVoteExtension | 本链默认禁用扩展，不以其传递私密数据 |

Rust 适配库存在 v0_38 的 FinalizeBlock 等接口，但默认实现不等于本链已校验。尤其不能保留示例中无条件接受提案的默认实现。[S15]

## 4.3 确定性规则

共识代码不得读取系统时间、HTTP、随机数、本机时区或有差异的环境变量。时间仅使用经过共识验证的区块时间。金额、份额、奖励、比率全用整数；排序采用字节序和固定 ID。HashMap 遍历不可直接影响根或奖励分配。

Rust 的 checked 运算遇到不可表示的状态必须产生规范错误或安全停机，不能 release 模式回绕、浮点舍入或默默饱和。交易范围错误只拒绝交易；发现已提交状态内部不变量破坏必须停止本机签名并报警，不能继续生成错误账本。

## 4.4 一个区块的执行顺序

在高度 h 的 `FinalizeBlock`：

1. 加载 h-1 已提交状态，核对链、版本与请求高度。
2. 读取实际 last_commit，对 h-1 的真实活跃集合记录签名参与分数；不信任本地配置的“预计验证者”。
3. 处理有效违规证据，先冻结/处罚相关验证者并创建需要的 SlashJob；重复证据不重复处罚。
4. 当 h 是新 epoch 首块时，结算上一 epoch 的发行和奖励；随后激活 pending 委托，再选取下一个验证集合。遇到未完成 SlashJob 的验证者不激活其新委托。
5. 按确定顺序推进有界的处罚与到期任务；涉及冻结状态的 claim 必须拒绝，不能抢先领取。
6. 依次执行用户交易：每笔创建状态子事务；成功才应用其所有写入与费用；失败整笔无资金变化。失败结果也记录稳定错误码。
7. 生成不包含 app hash 自引用的 compact block，计算其摘要；将摘要与公开业务事件摘要写入本高度状态。
8. 生成验证者更新、交易结果、事件与新 app hash；`Commit` 再原子持久化。

`ProcessProposal` 使用同一个执行计划（包含系统阶段）在临时状态上检查；本规范选择**拒绝包含不可执行交易的提案**。已经进入 FinalizeBlock 的异常无效交易仍必须以稳定失败结果处理，不能因共识输入触发 panic。PrepareProposal 的本地顺序可不同，但任何接受结果必须确定。

## 4.5 验证者集合生效高度

CometBFT 的验证者更新并非在发出更新的同一高度立即替换。实现必须按锁定版本的规则建立 `validator_set_at_height`，用官方一致性测试确认实际生效偏移；奖励、证据与在线率都用**实际生效集合**，而不是仅用 epoch 候选表。

在代码中提供唯一函数 `effective_set_at(height)`，所有模块调用它。测试必须覆盖 epoch 边界前后至少四个区块、旧键证据、新键激活和断点重放。禁止各模块自行假设偏移为 0。

## 4.6 状态键与根

```text
meta/version, meta/height, meta/chain_context
supply/issued, supply/burned, supply/shielded_total
shielded/tree_root, shielded/tree_frontier, shielded/nullifier/<nf>
shielded/anchor/<height>
validators/<validator_id>, validators/history/<height>/<id>
stake/pool/<validator_id>, stake/position/<position_id>
stake/pending/<activate_epoch>/<position_id>
exit/cohort/<validator_id>/<exit_epoch>
exit/ticket/<ticket_id>, exit/maturity_queue/<height>/<id>
commission/<validator_id>
fees/reserve, emission/carry
slashing/seen/<evidence_hash>, slashing/job/<id>
genesis/claim/<claim_id>
compact/hash/<height>, events/hash/<height>
```

票据 nullifier 和必要当前状态不能当普通历史随意裁剪。KV 根采用选定存储的真实证明格式；不要自己拼字符串当 Merkle proof。索引 PostgreSQL 可以删除重建，不影响链账本。

## 4.7 崩溃一致性

状态版本、根、区块执行标记、compact block 摘要和高度必须一并提交。若 app 已计算但 Commit 未完成，重启需从最后 durable 版本重放同一个区块，得到相同根，不能二次发行或重复扣款。

对磁盘满、fsync 失败、数据库校验失败和状态版本倒退，本机停止参与签名，界面显示恢复原因。不得自动清空数据库、重置签名状态后继续出块。

## 4.8 轻客户端看到的状态高度

区分 `block_height`、`state_height`、`header_height`。CometBFT 区块头 app_hash 对应的是此前提交的应用状态；客户端必须按该版本语义验证，不把同高字段混用。

本项目钱包将状态 h 的权益标记为可用前，必须取得覆盖该状态根的已验证头（通常为 h+1）以及相应的 KV/compact 摘要证明。交易可先显示“已入块，验证结算中”，但不能以未验证接口结果加可花费余额。正式确认时间目标包含这个额外验证步骤。

## 4.9 安全同步与弱主观性

钱包与快照节点采用轻客户端头验证、至少两个独立证人、固定 genesis hash 和已知可信检查点。可信期过期时进入重新建立信任流程，明确显示“需要更新可信检查点”，不能把多数 HTTP 端点一致当成无条件密码学安全。

新版本内置的签名检查点由多个独立发布者签署，包含高度、头哈希、生成时间与到期时间；发布签名只证明发布者背书，不赋予改账能力，也不能消除其共同作恶风险。长期离线恢复可让用户从独立来源核对检查点。信任期设置必须小于解除质押安全期。[S16]

## 4.10 验证集合延迟与退出暴露的统一边界

固定引擎语义：FinalizeBlock(H) 返回的集合更新于 H+2 生效。epoch 首块 H 产生新集合，旧权益退出 cohort 的暴露截止取 H+1；在 H+1 记录经过共识验证的链时间后再计算双重成熟条件。运行时还需核对 H/H+1/H+2 真实集合哈希，若不符则失败并阻断发布，不能用少加两块的退出期掩盖版本差异。[S22]

# 05　原生质押、持仓、退出与处罚

## 5.1 对象与字段

`Validator`：validator_id、operator_pubkey、consensus_pubkey、历史键映射、状态、佣金及延迟变更、元数据摘要、自质押位置集合、实际投票权、sequence。

`StakePool`：validator_id、generation、P（当前池中原生币原子单位）、S（份额总数）、待激活本金总数、最近结算 epoch。

`StakePosition`：position_id、owner_pubkey、validator_id、generation、shares、pending_amount、状态、sequence、created_height、加密恢复收据。它不是可转账代币，也没有公开支付地址字段。

`ExitCohort`：validator_id、exit_epoch、C（退出池当前资产）、U（退出份额）、exposure_end_height、maturity_height、maturity_time、状态。`ExitTicket`：ticket_id、position_id、cohort_id、units、sequence、已领取标记。

同一 position 可以部分退出产生多个 ticket。owner_pubkey 不可修改；找回通过恢复原密钥，不提供管理员改主人。因一次操作而暴露的同一 position 关联属于明确公开边界。

## 5.2 不依赖本地计数器的持仓密钥恢复

钱包保存高熵 `wallet_root`；用 HKDF-SHA256 派生独立 `stake_root`。每次创建持仓随机产生 32 字节 `position_nonce`：

```text
position_secret = HKDF(stake_root,
  info = "solo/stake-owner/v1" || chain_context || position_nonce, length=32)
owner_pubkey = Ed25519.public_key(position_secret)
position_id = SHA256("solo/position/v1" || chain_context || owner_pubkey)
```

所有串联字段固定长度或带显式长度前缀。HKDF 为现有密钥派生原语，本项目域隔离和用途仍需审查。[S17]

`position_nonce`、position_id、validator_id、创建意图写入一个加密恢复收据，使用独立的 `receipt_key = HKDF(wallet_root, "solo/receipt/v1" || chain_context)` 和 XChaCha20-Poly1305；AAD 绑定 position_id、owner_pubkey、validator_id。收据用随机 nonce、固定填充长度，不上报 receipt_key。

钱包全量扫描公开 compact receipts，本地尝试解密并重建持仓密钥，无需知道旧设备生成了多少地址或 nonce。客户端必须在提交前自己解密验证收据与派生公钥一致。恶意自造客户端可以把自己的恢复收据写坏，协议不应因此给它盗取他人资产的能力；恢复保证适用于正确使用的官方钱包。

## 5.3 创建与激活

Delegate 金额 D 必须达到最低额，owner 的新持仓所有权签名必须有效。链从私密交易的价值余额扣 D，建立 pending 持仓。Pending 不投票、不赚奖励，下一 epoch 在先结算旧池收益之后激活。

若目标已停用、tombstoned 或不接受新委托，则拒绝；激活时变为不合格则保留为 refundable_pending，允许持仓 owner 取回，不把钱留在无人处理的状态。

激活时：

```text
若 S=0 且 P=0：minted_shares = D
否则：minted_shares = floor(D*S/P)
要求 minted_shares > 0 且满足创建时 min_shares（或明确无滑点限制）
P' = P + D
S' = S + minted_shares
position.shares += minted_shares
```

使用 U256 乘法并 checked 转回 U128。舍入利益留在同一池，不能送入项目方账户。若 `P=0,S>0`，旧 generation 已资不抵债：停止新存款，旧份额价值为零，允许免费本地隐藏但不能假装恢复本金；必须清理/结算旧代后才能开启新 generation。

激活报价因周期收益而失效时，不自动降低 min_shares：将 pending 标为可退款，钱包说明原因。全新持仓不会通过抢在 epoch 最后一块存入而获得过去一整周期奖励。

## 5.4 池价值与奖励显示

位置理论价值 `floor(position.shares * P / S)`。部分退出按相同比例计算；当实际销毁的是该池全部剩余份额时，应取走全部 P，避免永久残余。显示金额精确到 8 位，内部不使用浮点。

“累计收益”按净值变化与存取事件记录分解为奖励、手续费、罚没和舍入。历史界面可用本地重放恢复，不用 `(当前价值-第一次存入)` 错算多次部分退出后的收益。

## 5.5 部分/全部解除质押

Unbond 指定 `shares_to_burn=q`、expected_position_sequence、min_gross_amount、max_fee、fee_source。金额按交易执行时当前池计算：

```text
x = P                          若 q == S
x = floor(q*P/S)                其他情况
P -= x; S -= q; position.shares -= q
```

`fee_source=SHIELDED`：费用由本交易的私密 Spend 支付，退出池增加 x。

`fee_source=RELEASED_VALUE`：费用 F 必须满足最低费且 `x>F`，退出池增加 `x-F`，公开动作释放 F 进入本交易价值平衡并由手续费消耗。这样全部可用余额已经质押时，也能由退出价值承担费。不允许任意把差额转给第三方。

原子创建退出票据。退出部分从请求确认时停止获得奖励；尚未结算的本周期奖励不会按离开时点单独追补，由仍留在池中的权益分配。这是明确的周期结算取舍，页面提示“本周期尚未结算部分可能不计入”。

退出的共识风险暴露截止必须覆盖下一 epoch 的集合更新延迟，不是点击按钮的一瞬间。固定 0.38 规则：在高度 H 返回的 ValidatorUpdates 在 H+2 生效；本链在下一 epoch 首块 H 更新，因此 exposure_end_height=H+1=当前 epoch 末高度+2。到达该高度才记录 exposure_end_time；升级引擎若改变偏移必须一起迁移并测试。不能仅以 epoch 末高度提前解除责任。[S22] 退出 cohort 按 validator_id 与 exit_epoch 聚合；同组每次加入资产 A 时按当前 C/U 汇率产生退出份额，首次 C=U=0 时 units=A。这避免已受罚 cohort 后加入的人被错误地重复扣同一损失。

## 5.6 退出票据到期与领取

默认须同时满足：

```text
current_height > exposure_end_height + unbonding_blocks
current_chain_time > exposure_end_time + unbonding_seconds
且该 validator 没有未完成的相关 SlashJob
且本票据未领取
```

到期时间使用 cohort 暴露截止时经过共识确认的时间记录；如果该 epoch 尚未结束，则显示预计时间，不伪造确定截止。成熟后将 cohort 置为 MATURE，不再受未来证据影响；配置关系必须保证此前可罚证据已过有效范围。

ClaimExit 将对应退出份额按当前 cohort 资产比例换成本币：最后一个份额领取全部剩余 C，其他按 floor；原子减少 C/U、标记票据并形成私密 Output。手续费同样支持 RELEASED_VALUE 或 SHIELDED。金额不足支付最小费的粉尘，可以在提供额外私密费输入后领取；不能称任何极小金额都保证零额外费用退出。

同一票据领取两次、序号落后、未成熟、未完成处罚任务，均拒绝。票据没有到期作废、维护者没收或必须登录服务器才能取回的条款。

## 5.7 验证资格和自质押

测试参数：最多 64 个活跃验证者，申请自质押至少 1000 SLC，普通委托最低 1 SLC。主网值必须在创世经济审查时明确接受，硬件低成本不表示席位资金门槛固定低廉。

每个 validator 至少有一个被 operator 签名绑定的自质押 position。自质押控制者与 operator 的关系通过一次性签名证明，不依赖实名。总池按有效权益排序，同权重按 validator_id 字节序。投票整数单位默认 1 SLC；总权重必须在 CometBFT 的安全数值范围内，超过配置安全上限时拒绝相关参数或状态变更；本版本不采用临时缩放算法，不能逐节点各算一套。

本版本选择在 genesis 固定 `power_unit` 并要求任何可达到的供给上限下总权重仍在规定 int64 安全范围；未满足时主网参数拒绝。技术金额上限不代表权重上限可忽略。

## 5.8 在线率与普通故障

只记录实际处于集合的签名机会。窗口 10000 次有效机会，至少达到完整窗口后判断；签署比例低于 95% 时 jail。未签区块没有对应贡献奖励，但普通短时断网不罚本金。jail 最少持续 7200 链上秒并经过 1440 块，再由 operator 签名申请恢复。

因为链需要超过三分之二投票权，足够多节点同时离线时仍会停滞；“自动下线”本身也需要链继续出块。不能编写绕过共识阈值的应急出块捷径。[S14]

## 5.9 可证明冲突签名与处罚

接受 CometBFT 提供、按对应历史集合校验且未过期的重复投票/轻客户端攻击证据；任何节点都可提交标准证据，不增加举报人持币门槛。以规范 evidence hash 去重。

测试默认罚没 5%（500 bps），validator 永久 tombstone。在线密钥误配置造成双签同样可能受罚。先对当前 active pool 按比例扣除并减少已发行存量，再对符合暴露截止条件的未成熟 exit cohorts 扣罚；佣金已独立记账部分不作为委托者本金，是否承担运营者附加处罚不得临时改变。

**公开风险：活跃池是共同承担未披露历史违规风险的池。**证据到达时仍在池内的权益可能受罚，即使用户在违规之后才委托但在证据公布前已激活。Pending 未激活本金不受该池扣罚。

为避免证据触发无界遍历，退出 cohort 扣罚由确定性 SlashJob 处理，每块最多处理固定数量 cohort（默认 128）。处罚生效起冻结该 validator 相关存入激活、退出和领取，直到任务结束；钱包显示“处罚结算中”。任务游标、已处理键、罚没总数与每个 cohort 版本原子提交，重启不重复扣罚。

cohort 满足 `exposure_end_height >= infraction_height` 才属于此次证据范围；成熟且已超过证据保护窗口的 cohort 不再扣罚。处理任务前后的总供给都保持会计不变量；冻结不能允许绕过 nullifier 或签名。每个 validator 身份只因第一次有效重大证据执行该永久处罚，后续同身份证据不能重复扣同一池；用户使用新身份仍需重新满足资格，不能假装识别同一自然人。

## 5.10 佣金与验证者变更

佣金 0–20%，建议默认 5%；提高佣金须提前 7 天链上时间且经过相应块数公告，单次提高不超过 1 个百分点，降低可在下一 epoch 生效。未激活的提高不能影响已经结算的奖励。

禁用、申请恢复、元数据修改、佣金修改、共识键轮换都需 operator 签名和 sequence。历史键绑定保留至证据窗口结束之后。轮换旧键不删除处罚责任；暂停节点界面不能直接修改链上活跃资格。

## 5.11 周期边界工作量与最后验证者

每个待激活epoch最多接受1000个pending持仓（全网逻辑预算，参考参数）。当前周期配额用尽时，新的Delegate明确返回E_ACTIVATION_CAPACITY，不先扣款后无限排队；用户可在下一周期重试。取消pending后释放尚未执行的配额，处理过的条目不会再次计数。这样被接受的正常pending仍能在下一epoch边界处理，且不会在一块内无界激活成千上万笔。每个epoch系统阶段预估并实测状态写入预算，块级最大10000指逻辑KV变更数，不是RocksDB内部物理页数。

验证者候选排序用持久化有序索引增量维护，不每块遍历所有历史注册身份。只有会影响候选资格/池值的变更更新索引，选择前64时按既定字节序处理同权重，节点本地缓存不影响结果。

任何主动Unbond/Disable不得使下一次选择时可用的合格验证者集合变为空；最后一个合格运营者须保留最低自质押，直至替代验证者满足条件。该约束只针对会清空集合的运营者动作，不阻止其他普通委托者按规则退出。返回E_LAST_VALIDATOR_BOND并说明原因，不伪装成网络故障。界面必须在最后验证者退场前提示此协议条件。

若有效证据等非自愿事件导致没有安全可用集合，节点不得向CometBFT返回非法空集合、忽略重大证据或无担保恢复出块。按事先定义的HALT_NO_SAFE_VALIDATOR_SET流程在可持久化的安全边界停签，保留可审查状态/事件；恢复需要公开的新网络决定和明确用户信任重建，不由后台任意复活被处罚身份。没有足够诚实在线权益时可用性本就不能保证。

# 06　发行、手续费、奖励与全局会计

## 6.1 参考经济配置

开发参考：8 位小数；创世总额 100,000,000 SLC；名义发行率每目标年 2%；目标块间隔 5 秒；每 epoch 720 块。**这是工程默认，不是用户已批准的主网经济政策，也不是保证年化收益。**主网不得偷偷采用测试分配或团队份额。

不写死 BTC 式 2100 万上限。当前采用持续协议发行，不设置任意管理员 mint。若主网决定固定上限，必须同时冻结发行曲线及长期安全预算，并更新数学模型与验收，不能只改首页显示总量。

## 6.2 总量会计

定义全都以最小单位记录的非负整数：

- Q：私密池总资产（公开边界余额，不是每个人的余额）；
- P：所有活跃/非活跃质押池持有的本金与已计入收益；
- D：待激活/可退款的委托本金；
- X：所有退出 cohort 的剩余资产，包括成熟未领取；
- C：验证者佣金应付余额；
- F：待分配手续费及整数余量储备；
- G：未领取的创世分配；
- T：流通与锁定之和，即当前存量。

```text
T = Q + sum(P) + D + sum(X) + sum(C) + F + G
T = genesis_supply + cumulative_minted - cumulative_burned
```

没有公开个人余额仍然可以维护 Q 的总资产账：公开的存入、取出、费用与发行对边界总额的影响是可知的，私密池内部转账不改变 Q。不得用全量解密来做账目检查。

## 6.3 发行算法

每个 epoch 完结一次结算。设 `Y=6,307,200`（365 天、每目标块 5 秒）、`L=720`、`bps=200`、`denom=10000*Y`。

```text
n = epoch_start_supply * bps * L + emission_carry
scheduled = floor(n / denom)
new_carry = n % denom
```

`epoch_start_supply` 是该 epoch 首块前确定的存量快照。名义年率依赖实际出块速度；停链时不凭墙上时钟补发“离线收益”。屏幕显示“协议名义发行率”，不能直接当作用户 APY。

按上一 epoch 实际共识参与计算 `score_v = sum(actual_voting_power_on_signed_blocks)`，缺席不加分。协议给每个有分数且剩余池 P>0 的合格验证者分配奖励。若 total_score=0 或无合格池，本期不铸币，carry 按预定余数更新，不累积未来可补领的整数“欠币”。

先执行 `minted=min(scheduled, technical_supply_cap-current_supply)`；达到技术上限后 minted=0，不结转被上限截断的整数发行。后续所有分配公式使用 minted 而不是未截断的 scheduled。`distributable = minted + old_fee_reserve`。各验证者按 `floor(distributable * score_v / total_score)` 获得毛额，整数余量保留 F；实际铸币 minted 计入 T。每池毛额按佣金 bps 拆为 C 与 P。不存在项目方社区池抽成，除非后续公开改变经济规则；本版无此入口。

被 tombstone/正在处罚或没有活跃权益的池不获得本期分配；必须在计算 total_score 前按同样资格过滤，避免分母包含不可付对象而造成账目悬空。自质押不足的验证者仍按实际有效块历史判断其既有权益，本期是否被排除由其结算时的安全状态决定，规则统一。

## 6.4 金额、精度与安全边界

Amount、Shares 使用 U128，外部金额限制 `<2^120`；乘除中间使用 U256，所有溢出拒绝。比例 bps 为 0..10000。JSON 用字符串，PostgreSQL 用 NUMERIC，Dart 与 JS 不将金额解析为 double/Number。

此外，供给到投票权的转换必须受 int64 限制：工程经济参数设置 `max_voting_power = 2^60-1`，mainnet manifest 的技术供给上界除以固定 power_unit 必须不超此上限。创世校验必须拒绝无法满足此条件的组合。系统不能声称无限增发却永远不检查边界；接近可表示/可投票上界时在预定高度停止额外发行，并显示协议技术上界，不能回绕或隐式改单位。

份额存入向下取整，最后全池退出取全部 P；cohort 领取同理。向下舍入的剩余仍在相同资产容器内，不转给维护者。重复拆单不得凭空获利，参考模型与属性测试覆盖分拆、合并、极小金额及全退出。

## 6.5 手续费规则

Fee 只接受本币，金额公开。手续费是阻止资源滥用的一部分，不保证能抵御一切垃圾流量。普通用户不需要选择 gas token。

参考最低费（原子单位）：

```text
base = 1_000
per_kib = 200
per_spend_proof = 500
per_output_proof = 500
new_position_surcharge = 100_000
validator_registration_surcharge = 100_000_000
min_fee = base + ceil(canonical_tx_bytes/1024)*per_kib
        + spend_count*per_spend_proof + output_count*per_output_proof
        + applicable_surcharge
```

手续费编码占固定长度，不因十进制字长改变资源模型。钱包构造完整交易后复核实际大小；若低于最低费则重新计划并再次呈现变化，不偷偷提高已确认费用。手续费不是法币定价，币价未知时不能宣传人民币几分钱。

区块资源拥堵以可审查报价和有上限的加费处理，本版不做复杂 fee market。有效但没进块的交易未扣款。已入块业务失败的原子交易本版不扣费；DoS 防护主要由提案拒绝无效交易、mempool 限额和前置验证承担，必须实测攻击负载。

## 6.6 避免“全部质押后无法付费”

钱包 Delegate 默认保留近期若干操作的费预算，并清楚区分可用与质押余额。即便用户使用其他客户端把可用余额全部锁定，Unbond 与 ClaimExit 支持从合法退出价值中支付费，CancelPending 与 ClaimCommission/Genesis 也可从释放额承担费。

若合法释放额不够最小费用，使用额外私密输入补足；钱包提示需要补充极少本币，不提供假的免费链上交易。第三方可以正常向该用户转入本币，但本版本没有无限代付或任意代操作授权。

## 6.7 创世闭环

主网创世条目采用公开领取权：claim_id、claim_pubkey、amount、可选公开锁定规则（本版不支持自定义释放脚本）、分配说明和独立审批签名。未领取部分记 G，领取需该 key 对完整交易签名，金额从 G 释放到私密 Output；领取一次即消耗。

初始验证者自质押直接记入明确的 genesis positions，计入 P，不在 G 重复计算。创世校验要求 `G+P+其他明确创世容器=genesis_supply`。不允许拿同一份币同时做创世收款和自质押。

测试脚本可用固定、公开、带巨大警告的测试种子；主网不能使用这些种子。真实领取者与运营者应各自生成私钥，只提供公钥和签名。维护者不能替他们持有主网私钥。

## 6.8 金额例子

一个池 P=1,000，S=1,000；用户投入 100，铸 100 份，池变 1,100/1,100。收到毛奖励 11，佣金 5%=0.55，P 增加 10.45，C 增加 0.55。该用户持仓价值为 100*1,110.45/1,100=100.95。

若全退出该用户的 100 份，扣明示费用后转成退出权益；不是系统重新凭空铸造 100.95。罚没减少 P/X 和 T；支付普通手续费只在 Q 与 F 间转移，不减少 T。参考程序仅用于验证这些整数会计关系，不是链实现或密码学测试。

# 07　钱包内核、安全恢复与网络隐私

## 7.1 密钥与 vault

随机数来自操作系统 CSPRNG，不用时间戳、钱包密码、手机号或 Math.random 生成种子。采用上游兼容的高熵恢复词编码，固定种子转换规则并提供向量；默认不额外增加容易遗忘的隐藏助记词 passphrase。

wallet root 派生支付花费/查看密钥、持仓根、收据加密根。不同用途使用不同域，资金密钥绝不派生给在线节点作为共识密钥。支付密钥与各 position secret 不通过日志、分析、剪贴板或后台上传。

Vault 使用随机 256 位 DEK；Argon2id 从用户本地密码和随机 128 位 salt 派生 KEK，用 XChaCha20-Poly1305 包裹 DEK。DEK 再加密 seed 与敏感元数据；数据库键从 DEK 独立派生。AEAD nonce 每次随机，AAD 包含文件版本、网络上下文和 vault UUID。

Argon2id 初始参数 m=64 MiB、t=3、p=4，属于 RFC 9106 对受限环境给出的配置方向；在支持平台评估耗时并只能按版本规则提高，不能不提示就降低到弱短密码保护。[S18]

密码要求至少 10 个字符，推荐长口令；不要求手机号、生物识别或短信。在线错误重试限流只能降低交互攻击，不能当作加密文件离线抗破解的保证。忘记密码可以恢复词新建 vault；忘记全部秘密无法由客服找回。

## 7.2 内存与操作系统

Rust 敏感对象使用可清零容器，尽量限制复制与存活时间；禁止在 panic、Debug、telemetry 中输出密钥。FFI 不把长久种子作为普通 Dart String 返回；备份显示使用短生命周期、明确授权的敏感会话，但不得宣传 UI 内存能够完全避免截屏/进程入侵。

不使用 `local_auth` 等生物识别授权流程，不把系统硬件钥匙设置为必须指纹/面容才可使用。可利用系统提供的非生物识别安全存储来保护辅助随机材料，但恢复不能只依赖某一设备。

锁屏/切后台自动遮盖敏感界面，默认后台超过 30 秒锁定、前台无操作 120 秒锁定。导出恢复词、改密码、签署 validator 变更、单笔超过本地大额阈值时重新要求本地密码。小额已解锁会话仍逐笔显示确认按钮，绝不默认自动支付。

Android 阻止普通系统截图的能力应启用；iOS 采取截屏检测、后台快照遮挡并说明不能完全阻止拍照。不得承诺所有平台均无法截图。

## 7.3 钱包数据库

SQLCipher 存储 notes、nullifiers、positions、本地交易计划、同步游标、contacts、invoices 与轻客户端可信状态。只存必要的私钥引用，种子位于独立 vault。

在同一个数据库事务中更新一批扫描数据、票据状态、position 事件与扫描高度。中断后可重扫同一区间而不重复入账。恢复必须从可信历史重建状态，而不信任同步服务给的 wallet_id 余额。

数据库备份不代替种子备份；种子备份不恢复从未上链的联系人备注，两类备份在页面上区分。加密备份带版本、校验和与 KDF 参数，导入前先检查大小和格式，不盲目信任用户提供的超大 KDF 参数耗尽内存。

## 7.4 转账计划状态机

```text
DRAFT → VALIDATED → INPUTS_RESERVED → PROVING → READY_TO_SIGN
→ SIGNED → BROADCASTING → PENDING → INCLUDED_UNVERIFIED
→ CONFIRMED
```

旁路状态：USER_CANCELLED、PROOF_FAILED、NETWORK_UNKNOWN、EXPIRED、CONFLICTED、REJECTED。

输入在本地预留防止两个窗口双花；保留 owner/plan_id 和到期高度。解锁预留前必须确认原交易没有待确认或已花费状态。NETWORK_UNKNOWN 不允许直接重建另一笔付款。原交易可逐字节重播；重新报价/重新构造需要新确认。

广播成功后保存完整 envelope 和 tx_id；本地断电恢复后先追踪它。UI 时间进度只表示阶段，不伪造证明或到账百分比。取消证明任务可终止本地计算，但不能取消已经被网络确认的交易。

## 7.5 收款地址与二维码

地址沿用选定上游编码及新的本链 HRP；给每笔收款生成新 diversifier。展示标签仅本地联系人别名，不作为链上身份认证。

`solo:<address>?amount=<decimal>&network=<chain_context_hex>&invoice=<base64url>&expires=<unix_seconds>` 为产品 URI。地址、金额上限、字符集、链上下文和参数长度严格校验；不执行其中的 URL、脚本或任意深链动作。未知必要参数拒绝，未知可选参数只忽略显示，不进入交易授权。

invoice 字段进入加密 memo，不公开；expires 控制支付请求界面，不是所有链上转账的撤销权。扫描网页二维码不得打开摄像头之外的任意系统权限。

## 7.6 Tor 与统一网络出口

所有钱包链查询、广播、参数下载和检查点更新经 Rust NetworkClient；Arti 支持作为嵌入式 Tor 客户端，但移动端生命周期与构建仍需本项目验证。[S19]

默认 privacy_required=true。Tor 建链失败、DNS 失败或网关不可用时显示真实失败与重试，不切换 Flutter HTTP 直连。使用远端名称解析，不先向本地 DNS 查询私密目的地址。对应用中所有 HTTP 客户端做静态审查与抓包测试。

手机 app 更新由平台渠道处理，不宣称因此没有任何平台可见元数据。节点 P2P 网络不使用钱包默认 Tor 策略来保证性能，也不向用户宣传节点 IP 匿名。

## 7.7 同步内容、完整性与隐私

每个 compact block 包含固定高度、交易摘要列表、output payload、nullifier 列表、承诺树增量与公开持仓收据/事件。其规范摘要被写入链状态，客户端用已验证根验证摘要，然后连续重算树。服务器漏掉 output、删掉 receipt 或重排事件会导致摘要/连续性不符。

不得让服务器按用户私钥、完整查看密钥、地址列表筛选数据。历史 memo 可按标准匿名区块批次下载，而不是直接暴露“我关心这个地址”。持仓查询是公开的，但钱包仍优先从通用事件恢复，避免对同一批 position 发查询造成聚类。

轻客户端验证只能证明内容和一致性，不能强迫服务器提供数据；所有端点拒绝服务时显示不可同步，不伪造当前余额。至少三个独立服务配置，连接到两个验证证人，缓存选择不要形成全体用户的唯一单点。

## 7.8 带宽与手机能力的真实边界

完整本地扫描会随全网使用量增长。计算例子：若 compact 平均 1 KB/交易、持续 20 TPS，仅 compact 原始流量约 1.728 GB/日，尚未计算传输开销。这是示例推算，不是本项目已经测得的尺寸。

因此“节点可验证 20 TPS”不自动意味着手机可廉价无限同步。正式容量选择必须同时通过节点 CPU、手机扫描、数据流量与恢复测试。UI 提供同步数据估算、按需暂停和 Wi-Fi 提示；不能悄悄用上传查看密钥换取速度。

完整交付不等于无限容量：mainnet profile 在实测报告中固定区块上限，若钱包日常预算不通过，就降低该 profile 的吞吐上限而不删掉功能。任何降低隐私保证的服务端扫描方案均不属于本版默认实现。

# 08　全量页面、交互与文案规格

## 8.1 全局设计规范

手机底部导航为“钱包、质押、记录、设置”。首页三个主操作为“收款、转账、质押”，不放行情、杠杆、推荐收益榜或广告。中文版与英文版必须完整，无生物识别词条和手机号注册页面。

# 09　公开 API、本地 SDK、错误与幂等

## 9.1 三类接口必须分开

公开 HTTP/gRPC：只提供公开数据、证明和交易广播，无钱包注册、无余额修改、无恢复词上传。

钱包 FFI：进程内本地调用，处理解锁、扫描、计划、证明和签名，不监听公网端口。

节点管理 IPC：Unix domain socket 或 Windows named pipe，OS ACL + 随机会话 token；仅管理本机节点，不具备钱包资金签名权限。

`contracts/openapi.yaml` 定义公开 REST；`contracts/solo.proto` 定义 envelope 与查询结构；`contracts/local_sdk.json` 定义本地接口签名和访问等级。它们是需要实现的合同，不是已经存在的服务。

## 9.2 公开服务

| 方法/路径 | 用途 | 信任要求 |
|---|---|---|
| GET /v1/network | chain_context、genesis hash、版本、资源参数 | 与内置/核对过的 manifest 比较 |
| GET /v1/headers | 从起始高度获取头与实际验证集合 | 本地轻客户端验证，限制每批数量 |
| GET /v1/compact-blocks | 通用 compact block 区间 | 必须带 hash/state proof，验证完整性 |
| POST /v1/transactions | 提交 canonical envelope | 返回只是接收状态，不等于到账 |
| GET /v1/transactions/{tx_id} | 入块/待定与结果证明 | 验证 inclusion、结果及对应头 |
| GET /v1/state/proof | 指定公开 key 的值/不存在证明 | 精确绑定 state_height，不信单独 value |
| GET /v1/validators | 公开验证者目录 | 分页，状态结果可附证明 |
| GET /v1/validators/{id} | 验证者状态与佣金 | 验证状态证明 |
| GET /v1/positions/{id} | 公开独立持仓状态 | 钱包优先从通用同步恢复，减少聚类 |
| GET /v1/exit-tickets/{id} | 退出等待、当前值、证明 | 不以接口估算代替签名时链验证 |
| GET /v1/supply | 发行与容器总账 | 与状态根证明绑定 |
| GET /v1/fees | 当前固定费参数与报价高度 | 费用公式钱包也独立实现 |
| GET /v1/checkpoints | 多方签名检查点候选 | 不是自动信任入口 |
| GET /health/live | 进程存活 | 不包含内部地址、敏感配置 |
| GET /health/ready | 同步与服务就绪 | 不表示链已去中心化或资产安全 |

所有主网钱包请求走 Tor。body/query 严格上限；范围请求 limit 默认 100、最多 500 个小对象，compact 最大批次通过总字节限制独立限制；禁止任意反射查询或不受限全文搜索。公开接口不要求以手机号注册 API key。

## 9.3 API 共同字段

ID 为规范小写十六进制（32 字节则 64 hex）；地址按 HRP 规范；金额是十进制字符串，无正号、指数、千位分隔或负值。时间用 RFC3339 UTC，内部 chain_time 用 seconds/nanos 的确切整数表示。所有返回含 `protocol_version`、`state_height`、`verified_header_height`（服务声明，客户端仍要验证）。

证明数据固定标明 proof_format 与版本。空值必须区分不存在、未索引、节点没同步及未知交易，不能统称 NOT_FOUND。区块浏览器索引未知不说明交易没有发生。

## 9.4 广播幂等与重试

客户端用 tx_id 作为幂等标识。相同字节重播最多得到相同交易的状态；服务器不得替用户改费、替换收款输出或重新签名。不同 tx_id 即使备注相同也不是同一笔链上付款，不按 invoice_id 在全网查隐私交易。

HTTP 超时、429、503 返回可重试信息和 Retry-After，但钱包先保持原交易预留。已确认重复提交返回 CONFIRMED 状态与证明；mempool 暂时缺失返回 UNKNOWN/MEMPOOL_EVICTED，不宣布支付失败。

## 9.5 钱包 FFI 组

生命周期：`wallet_create/wallet_restore/wallet_unlock/wallet_lock/wallet_change_password/wallet_delete_local`。

安全：`backup_begin/backup_reveal_chunk/verify_backup/export_encrypted_backup/import_backup`；导出每次有本地授权，不允许任意对象 Debug 输出。

同步：`sync_start/pause/status/import_checkpoint`；进度事件为不可变 DTO。

支付：`receive_request_create/parse_payment_uri/plan_payment/prove_plan/confirm_and_sign/broadcast_signed/transaction_status/rebroadcast`。

质押：`validators_list/plan_delegate/list_positions/plan_cancel_pending/plan_unbond/list_exit_tickets/plan_claim_exit/plan_claim_commission`。

节点权限：`parse_node_request/approve_validator_request/export_approval`。该组只接受枚举的已知请求和字段，禁止 `sign_arbitrary_bytes`。

本地数据：`contacts_* / invoices_* / export_history / diagnostic_preview`。

所有 plan 带 plan_id、chain_context、state_height、effect_summary、fee、expires_height、input_reservations。`confirm_and_sign` 只签用户刚看过且摘要未变的 plan；后台变更任何金额均失效。

## 9.6 本地 IPC

node-agent 提供 `InspectHost, GetStatus, InstallRuntime, Start, Stop, ImportVerifiedSnapshot, CreateConsensusIdentity, MakeRegistrationRequest, ApplySignedOperatorTx, ExportDiagnostics, PrepareUpgrade, ApplyApprovedUpgrade`。

默认只本机。凭 OS ACL 和短会话 token 访问；请求 ID、操作类型、参数完整性与权限分级记录到脱敏日志。不能把任意字符串传给 shell；可执行路径来自签名安装清单且无 shell 插值。

手机与桌面交换带 nonce、chain_context、node_fingerprint、过期时间/高度的 QR 包；手机签过的包只授权明示动作。没有可信本机配对时，不开放远程管理 HTTP 端口。

## 9.7 错误码族

格式/版本：E_BAD_ENCODING、E_SIZE_LIMIT、E_UNSUPPORTED_VERSION、E_CHAIN_MISMATCH。

密码学：E_INVALID_PROOF、E_INVALID_SIGNATURE、E_INVALID_BINDING、E_DOUBLE_SPEND、E_UNKNOWN_ANCHOR。

资金：E_INSUFFICIENT_FUNDS、E_INSUFFICIENT_FEE、E_AMOUNT_RANGE、E_SLIPPAGE、E_STALE_QUOTE。

质押：E_POSITION_NOT_FOUND、E_OWNER_MISMATCH、E_SEQUENCE、E_VALIDATOR_INELIGIBLE、E_EXIT_IMMATURE、E_ALREADY_CLAIMED、E_SLASH_PENDING。

网络/客户端：E_NETWORK_UNKNOWN、E_PRIVACY_UNAVAILABLE、E_TRUST_EXPIRED、E_CONFLICTING_HEADERS、E_SCAN_INCOMPLETE、E_VAULT_LOCKED。

节点：E_SIGNER_ROLLBACK、E_DOUBLE_SIGN_ATTEMPT、E_DISK_FULL、E_SNAPSHOT_INVALID、E_PROTOCOL_UPGRADE_REQUIRED。

错误响应不回显 seed、地址列表、完整证明 witness 或未脱敏请求。内外码映射需完整测试，不允许前端因未知错误默认显示成功。

## 9.8 浏览器只读补充接口

`GET /v1/blocks`（cursor/limit，最多100）、`GET /v1/blocks/{height}`（头、公开tx_id与证明）、`GET /v1/validators/{id}/events`（公开佣金/证据/变更，分页）、`GET /v1/upgrades`（多方签名软件升级公告）。同样不接受恢复词或私密地址查询。升级公告仅是发布者建议；网关返回某高度不代表拥有修改共识或自动安装的权力。

REST共19个操作；solo.proto中只定义其中4个高频gRPC镜像，其余通过REST，不要求为所有接口维护第二套独立业务规则。

补充质押错误：E_ACTIVATION_CAPACITY表示本次激活周期容量已满，未扣款；E_LAST_VALIDATOR_BOND表示本次主动操作将清空合格验证集合，需要替代节点，不能通过跳过自质押规则绕过。

# 10　数据模型、索引与迁移

## 10.1 数据真相的三个层级

链共识状态是资金真相；钱包数据库是用户可解密资产与本地事务缓存；公开索引是可重建的读模型。不能通过修改 PostgreSQL 或管理面板改变链上余额，也不能把索引扫描到的明文记录当作私密余额数据库。

## 10.2 钱包表

`wallet_meta`：vault UUID、版本、chain_context、backup_verified、最后可信/扫描高度。

`notes`：commitment 主键、加密解密结果、value 字符串、asset_id、位置、nullifier、spend_status、created_height、reserved_plan_id。只有已验证本币且非空票据可计入可花费余额。

`plans`：plan_id、kind、effect_hash、状态、原 envelope、tx_id、有效高度、创建时间、脱敏显示摘要；敏感 witness 不持久化或单独短期加密，过期清除。

`positions`：position_id、validator_id、owner key reference、加密 nonce、shares、pending、sequence、状态高度。

`exit_tickets`：ticket_id、position_id、cohort_id、units、到期双条件、领取状态和已验证高度。

`transactions`：tx_id、类型、方向、金额、费用、阶段、高度、发票本地关联、memo、本地标签。

`contacts`、`invoices`、`invoice_payments`、`checkpoints`、`scan_batches`、`schema_migrations`。

表中金额以规范十进制字符串保存或固定 16 字节数值保存；不要使用 SQLite REAL。SQLCipher 是整个数据库文件真实加密，WAL/临时文件也必须符合其安全方式。

## 10.3 公开索引表

`blocks`、`transactions_public`、`validators`、`validator_changes`、`stake_positions_public`、`exit_cohorts`、`exit_tickets_public`、`supply_snapshots`、`evidence_events`、`indexer_cursor`。

公开 transaction 表没有 from_address、to_address、private_amount 列。允许存公开手续费、action type、承诺/nullifier 摘要、position_id 等本来公开的数据。不得从运营者日志补出用户 IP/设备身份表。

`contracts/indexer.sql` 提供初始建表合同。只读服务数据库角色只有 SELECT；索引器有独立写权限；没有对外 SQL 接口。索引器读取新块时先验证上游链/高度，原子写入整块与 cursor，唯一键确保重复扫描无重复行。

## 10.4 Compact 数据与保存

compact records 必须保存足以恢复支付与持仓的密文、树增量和恢复收据；不能只保存明文 UI 摘要。历史数据按 immutable chunk 保存到至少两个独立来源，chunk hash 被验证链状态绑定。

家庭节点可裁剪已经过安全窗口的区块全文和非必要查询索引；仍保留当前状态、nullifier、可信同步所需元数据。公开历史服务保存全部恢复数据，用户可自己运行。任何服务移除历史数据前须有可验证备份与公告，不把历史恢复建立在唯一商业服务器上。

## 10.5 数据迁移

每次数据库升级有递增版本、迁移文件 checksum、测试前后统计。钱包迁移前创建加密备份，先完整校验再原子切换，不在失败时删除旧 vault。任何迁移不改变 seed/key derivation。

链状态迁移仅在已公布协议升级高度执行，输入旧状态根、迁移二进制 hash、输出新状态根及不变量报告必须可重演。多个独立平台对同一快照迁移应得到相同根。

索引 schema 可以独立升级，失败时从最后确认 cursor 重建；浏览器临时不可用不影响链共识与钱包私钥。

## 10.6 幂等/一致性索引

node `FinalizeBlock/Commit`、indexer 每块写入、wallet 每批扫描和发票对账都有独立幂等键。不能用现实时间作为唯一事件 ID；采用 chain_context+height+transaction_index+event_index，或者已规范定义的 tx_id/position_id。

支付入账、持仓生效、退出领取必须以相应高度的状态 proof 通过为准；跨服务数据显示不同高度时附带高度，不静默混成一个“实时余额”。

# 11　家庭节点、签名器与完整部署

## 11.1 家庭节点资源目标

设计测试目标：普通四核处理器、8 GB 内存兼容/16 GB 建议、512 GB SSD、稳定宽带、可用上行 10 Mbps，不要求独立显卡。是需要测量的目标，不是已经保证的最低配置。

默认不保留全文历史索引，不向公网开放 RPC。区块验证、状态写入、快照与节点同步各自限制 CPU、并发与磁盘预算。需要测量满负载稳态、突发、初次同步、恢复、证明垃圾流量和数据库增长，不用空链跑通证明“家用可用”。

Windows 提供受管理 WSL2 运行时，界面原生 Flutter；磁盘放在 WSL2 的 Linux 文件系统，不默认放慢速跨文件系统路径。说明休眠、Windows 更新和 WSL 生命周期会影响在线率。

## 11.2 进程布局

`solo-node-agent` 管理三种子进程：`solo-app`、固定版本 `cometbft`、`solo-signer`。应用和签名器使用单独低权限用户/目录。ABCI 与 signer socket 仅本机开放，P2P 可按角色配置公开；任何公开 RPC 需要独立 gateway/sentry。

默认监听：CometBFT P2P 26656；CometBFT RPC 127.0.0.1:26657；ABCI 127.0.0.1:26658；公开 gateway 8443（通过 TLS 入口）；指标 127.0.0.1:9100；signer 与 agent 使用本机 socket。端口只是工程配置，不应在 UI 强迫普通用户理解。

## 11.3 无公网 IP 的接入

家庭节点主动连接至少两个独立哨兵/对等接入节点，避免强制端口映射。接入地址来自签名网络配置且可由用户添加独立来源。不能所有节点只连项目方一个中转。

此结构改善家庭网络兼容性，但不能保证所有运营商环境可连，也不能保证隐藏验证者 IP。连接失败应诊断 NAT、DNS、时间与哨兵可达性，不自动打开路由器所有端口。

## 11.4 共识签名器

共识密钥独立随机生成，不由资金 seed 派生。每个 signer 只服务一个明确的 chain_context 与 validator identity。签名请求检查 chain_id、height、round、step 及完整 sign bytes。

为每个 `(chain_id,height,round,step)` 记录消息摘要和签名。相同键相同消息返回已持久化原签名；相同键不同消息拒绝。签名前先记录 intent，完成签名后将签名与安全水位原子 fsync 后才返回网络。崩溃中途恢复必须保持“不签冲突消息”的原则。

锁文件仅防本机双实例，**不能证明另一台克隆电脑不存在**。复制密钥和签名数据库到两台机器仍可能造成双签。钱包/节点文档不得承诺自动检测所有克隆；迁移必须停旧 signer、核验最新安全状态，优先通过协议轮换新键，保留旧键历史责任。

检测签名数据库回退、缺失、损坏、nonce/水位不一致时 fail closed。禁止为了重新启动而自动删除 `priv_validator_state` 或导入一个更老的备份继续签。

## 11.5 手机与节点权限绑定

node-agent 生成请求：版本、chain_context、request_id、node_fingerprint、consensus_pubkey、动作、参数摘要、到期高度和时间、新键 PoP。二维码只包含请求或受认证的本地传输定位，不包含资金秘密。

手机解析后展示完整关键字段，用 operator key 或需要的资金 key 签署限定动作，再将签名 envelope 回传。桌面只能广播，不能修改。Request 重放因 request_id/sequence/有效期失效，别的链重放因 chain_context 失效。

注册与自质押是两类权限：共识密钥可以证明它控制节点身份，但不能授权扣款；资金持有人确认自质押才锁币。

## 11.6 完整 localnet

`just localnet` 最终需生成并运行 4 个**独立应用进程+独立 CometBFT 进程+独立 signer**，不只是在同一进程内建四个结构体。再启动 gateway、indexer、PostgreSQL、explorer 和观测服务。

测试账户使用专门公开测试种子，程序启动必须打印“测试网、无真实价值”。开发环境允许目标块间隔与 epoch 缩短，但资源验证、安全签名、真实证明和供给不变量不可关闭。故障测试关闭节点必须影响真实 BFT 网络。

`just localnet-down` 默认不删除密钥和数据库；破坏性重置需要 `--destroy-test-data` 且 chain profile 必须是 localnet。

## 11.7 公共服务部署

主网服务按角色分开：独立验证者、哨兵、公共查询、归档/快照、只读索引、浏览器静态资源。项目可运营部分服务但不拥有其他验证者密钥。至少有独立组织控制的查询/归档与检查点来源，不能把“同一云账号的三个地址”当作三方独立。

容器非 root、只读 root filesystem、最小 capabilities、资源限制与磁盘配额。镜像固定 digest，配置不含私钥。私钥通过受限本地文件或正式 secrets 机制注入，不能出现在 compose、GitHub issue 或安装日志。

## 11.8 CLI 必须提供的命令

```text
solo version / doctor
solo wallet create|restore|receive|balance|send|history|backup
solo stake validators|delegate|positions|unbond|exits|claim|refund-pending
solo validator register|status|update|unjail|disable|rotate-key|claim-commission
solo node init|start|stop|status|snapshot-export|snapshot-import
solo signer init|inspect|migrate-check
solo genesis build|validate|claim
solo network verify-checkpoint|verify-manifest
solo release verify|preflight
```

每个命令支持 `--network` 与 `--json` 输出；敏感密码由安全提示或受限文件描述符输入，禁止普通 `--password` 参数写入 shell history。CLI 与图形钱包共用 Rust 内核，不另写第二套会计与签名逻辑。

## 11.9 注册/轮换的 PoP 多轮交换

节点最初二维码中的 PoP 是对带域的随机配对 challenge 的证明，不是尚未构造交易的最终 effect_hash 签名。流程固定为：节点提供已证明控制的共识公钥与请求 → 手机计划交易、生成真实证明并完成资金/operator授权 → 将只缺 CONSENSUS_POP 的 typed envelope 回传本机 agent → agent 仅对该已解析的 Register/Rotate 操作、匹配本机共识公钥的最终 effect_hash 添加域隔离 PoP → 手机验证返回主体未变、全部授权/费用有效，保存最终 envelope 与tx_id后广播。不能复用第一步的挑战签名冒充最终交易授权。

这套交换使用有界动画二维码或已配对认证传输；不把付款私钥给电脑。agent 的PoP入口仅支持这两种明示类型，检查nonce与有效期；signer不提供任意字节签名RPC。普通支付与日常委托不需要该多轮流程。operator key以wallet_root独立域派生并通过恢复测试；本版同一operator对应一个validator_id，多个独立身份需单独钱包/操作密钥，不引入平台账号。

# 12　运维、升级、监测与事故处理

## 12.1 监控指标

节点：高度、最后提交时间、有效 peer、漏签窗口、CPU、RSS、磁盘可用、状态写入时间、验证耗时、mempool bytes、拒绝原因、时钟偏差与 signer 水位。

网关：同步落后高度、请求延时、错误率、批次大小、Tor 接入可用性与资源配额。索引：已索引高度、验证根、落后、重放错误。供给：T 与全部容器和的差、发行/罚没累计、负值/溢出预警。

不采集用户 IP 交易画像、wallet_id、私钥、查看密钥、账户余额标签或广告 ID。公开基础设施不可避免获得的网络日志应最少化，默认不持久化完整访问参数；维护者要说明自己控制服务的数据政策，不能替所有独立运营者保证不记录。

## 12.2 告警与动作

| 告警 | 本机动作 | 禁止行为 |
|---|---|---|
| signer 回退/冲突请求 | 停签并持久化报警 | 删除安全状态后自动重启 |
| 磁盘不足/数据库损坏 | 停止新写入与签名，保留诊断 | 自动清空数据 |
| 两个有效冲突头 | 钱包/节点进入冲突处理 | 随便选高度更高那条 |
| 网关不可用 | 切换独立服务并维持隐私连接 | 静默直连或假造确认 |
| 会计不变量失败 | 停止本机状态推进，导出脱敏摘要 | 管理员手工改余额修平 |
| 重大漏洞披露 | 公开协调补丁与验证者选择升级 | 后台强制转移用户资产 |

## 12.3 快照

快照包含确定高度状态、根、节点版本、网络、chunk 哈希、格式和大小上限。导入时先核验轻客户端覆盖的状态根，再在隔离目录逐块恢复和验证；完整通过后原子切换。

快照不包含生产共识私钥或资金私钥。同步数据和 signer 防双签状态分别维护；下载公共快照不能覆盖本地签名水位。每种正式平台都需进行至少一次全新目录恢复和断点中断恢复演练。

## 12.4 软件与协议升级

普通 UI 安全补丁与链规则升级分开。发布清单包含版本、源码 commit、构建环境、SBOM、依赖锁、二进制哈希、兼容协议、升级高度、迁移摘要、签名、公钥轮换说明。

客户端先验证发布签名和下载哈希，展示变更并得到用户许可。网络配置不能下发任意可执行命令。用户已选择的自动安全更新不得包含未经再次许可的共识规则和资金授权改变。

链规则升级由维护者公开发布、独立验证者审查并安装。在明确高度统一执行已审查迁移；旧节点遇到不支持版本停止参与，不私自降级。没有一个项目方管理密钥能单独替全网安装升级。

软件版本一旦产生新的已确认状态，不能简单回滚数据库/二进制继续签旧链。事故恢复采用公开协调的新修复版本和确定迁移；若发生共识破坏，明确是社会协调和重新确认信任，而不是正常“自动回滚”。

## 12.5 签名与构建供应链

release signing key 与 genesis key、validator operator、consensus key 和钱包 seed 完全独立。签名密钥保存在受控离线环境或独立硬件，不硬编码在 CI。

主网安装包至少有两个独立构建者复现主要核心二进制哈希；平台特有签名封装可有不同外层哈希，需对比签名前 payload。SBOM、许可证和安全通告复核进入发布证据，不仅扫描 package.json。

## 12.6 应急演练场景

单节点断电；超过三分之一投票权离线；隔离成两个分区；两台机器重复运行同一 signer key；数据库回滚；恢复数据被替换；网关发假状态；费用池异常；版本升级一半节点拒绝；全体查询服务不可用。

演练记录真实触发方式、实际高度、签名器行为、是否停链、恢复过程与未解决影响。演练结果只能由测试执行记录产生，不允许把文档中的“期望结果”复制到报告冒充通过。

# 13　威胁模型、安全边界与安全验收

## 13.1 保护目标

不能未经有效授权花费私密票据、提取持仓、领取退出或佣金；不能凭空制造余额；不能重复花费；普通支付不公开身份/金额关联；客户端不泄露秘密；链不会因为不同平台实现差异产生不同合法状态。

不承诺防住已取得全部钱包秘密的攻击者、完全被控制的操作系统、用户自愿签出的有效转账、交易对手掌握的现实信息、全球流量分析，或恶意权重突破共识假设后的全部情况。

## 13.2 威胁—措施—测试映射

| 威胁 | 必须措施 | 必须测试 |
|---|---|---|
| 助记词/密码泄露 | 本地加密、用途隔离、无秘密日志 | vault 文件、内存与日志检查 |
| 钓鱼签名 | 完整 effect summary、无任意签字节接口 | 改地址/费/网络/动作后旧签名失效 |
| 验证者盗取委托 | 委托由独立 position key 控制 | operator/consensus key 均不能 ClaimExit |
| 重放/双花 | chain_context、expiry、sequence、nullifier | 跨链、同块与跨块冲突 |
| 增发漏洞 | 绑定签名、公开释放授权、供给不变量 | 伪造释放/负值/外国资产/重复领取 |
| 证明参数错用 | 精确电路/参数/版本哈希 | 换验证键、公共输入顺序等全部失败 |
| 假 RPC/假余额 | 头与 KV/compact 证明验证 | 篡改值/漏事件/错高度 |
| 节点密钥克隆 | durable signer、单写者迁移 | 同 H/R/S 异消息拒签、重启不回退 |
| 共识 DoS | 字节/证明/写入预算、前置检查 | 超大数据、畸形证明、mempool 饱和 |
| 数据库崩溃 | 事务、fsync、版本重放 | 每个提交点断电注入 |
| 恶意升级 | 源码/二进制签名、独立复现 | 伪造清单、签名轮换、回滚攻击 |
| 网络去匿名 | Tor 统一出口、无静默降级 | 抓包、DNS 泄漏、客户端其他 HTTP |
| 质押关联 | 独立 key 与收据加密、明确公开边界 | 不出现支付地址，公开 position 可关联如实展示 |
| 供应链问题 | 锁依赖、SBOM、许可证与通告复核 | 恶意包、浮动依赖、生成代码差异 |

## 13.3 密码学差异审查

审查至少覆盖：选用上游源码及已知问题，电路/参数是否完全一致，Spend/Output 公共输入是否正确，原生动作贡献价值余额符号，effect hash 是否覆盖全部授权字段，跨网络隔离，原生币资产闭包，随机数和 nonce 用法。

“有上游审计”仅说明对应代码在其范围和时间接受过检查，不证明本项目新增组合和钱包安全。外部审查不能由 Codex 自己编造一个签名文件代替。[S20]

## 13.4 权限矩阵

| 权限/角色 | 花私密币 | 取某持仓 | 改验证者元数据 | 共识签名 | 改任意余额 |
|---|---:|---:|---:|---:|---:|
| 支付花费 key | 是 | 否，除非同钱包另派生并持有相应 position key | 否 | 否 | 否 |
| position key | 否 | 仅自己的持仓/票据 | 否 | 否 | 否 |
| operator key | 否 | 仅另行证明自己控制的位置 | 是 | 否 | 否 |
| consensus key | 否 | 否 | 否 | 是 | 否 |
| 查看 key | 否 | 否 | 否 | 否 | 否 |
| 查询服务 | 否 | 否 | 否 | 否 | 否 |
| 项目维护者/发布 key | 否 | 否 | 否 | 否 | 否 |

## 13.5 发布阻断条件

存在未解决的 Critical/High 安全问题；核心证明或授权用 mock；随机数不合格；真实资产配置含测试种子；签名键与资金键混用；公网暴露本地签名接口；错误快照被信任；会计模型与链实现不一致；任何支持平台金额编码不一致；mainnet 对外承诺与实际隐私边界不符。

阻断不意味着放弃开发：完整代码、测试网络与安装包仍应完成。它意味着不能把尚未达到条件的软件标成可安全承载真实资产。

# 14　全量测试、性能与最终完成定义

## 14.1 测试金字塔

数学/类型单元测试；协议 property tests；密码学固定向量与负例；实际多进程共识集成；钱包/节点界面 E2E；网络隐私抓包；平台构建；故障注入；资源性能；外部审查与独立复现。

## 14.2 必须通过的资金流程

创建并备份钱包 A/B → 创世领取或测试发放 → A 私密支付 B → B 验证到账 → B 创建独立持仓 → 激活 → 节点产生多个真实 epoch → B 离线后恢复发现收益 → 部分退出 → 等待双条件 → 领取并再付给 A → 恢复 B 到新设备 → 找回剩余票据、持仓与退出状态。

第二条：全部余额锁定 → RELEASED_VALUE 承担 Unbond 费用 → 到期继续以释放额承担 Claim 费用 → 可用余额恢复。第三条：验证者公开违规 → 处罚任务完整结算 → 本金/退出池/总供给同步减少 → 未成熟不能抢领 → 剩余权益仍可退出。

## 14.3 密码学与协议负例

错误 Spend proof、错误 Output proof、错误 binding signature、错误公钥/群编码、错误 proof manifest、跨链旧签名、错费用、改收款密文、重复 nullifier、同块两个花费、过期 anchor、超范围 amount、构造非本币正价值、伪造 Claim 正释放、错误持仓主人、旧 sequence、未知业务动作。

每个字段篡改必须覆盖，不能只测试一个“签名错误”例子。原语固定向量在所有正式目标平台一致；任何平台出现不同 envelope/哈希/签名验证结果即阻断。

## 14.4 质押数学属性

所有合法序列保持总供给不变量；存入/退出/领取原子；ceil/floor 边界无套利；最后持仓和最后退出份额不遗留无主余额；pending 不提前赚奖励；离线不造币；处罚不重复；处罚作业中断恢复不重复扣罚；佣金不超过预定比例；更换共识键不清历史证据；所有份额归零或 P=0 状态有确定处理。

参考 Python 模型只验证若干整数关系，是独立 oracle 的起点，不替代 Rust 链实现的 property tests，更不验证零知识证明安全。

## 14.5 共识与故障

4 节点本地网络：逐个停机、重启、消息延迟、网络分区、同一交易重复广播、不同 mempool 顺序、错误提案、重放同一块和验证者更新偏移。超过三分之一权重故障时观察真实停滞，不通过降低阈值使测试“成功”。

64 活跃验证者实验用独立进程与可控网络拓扑，不用 64 个线程冒充独立故障域。此实验也不证明现实权重已经独立控制。

## 14.7 隐私测试

## 17.2 参数关系验证

`unbonding_seconds > evidence.max_age_seconds + trust.max_clock_drift_seconds`，`unbonding_blocks > evidence.max_age_blocks`，`trust_period_seconds < unbonding_seconds`。链在超慢/超快出块下仍需满足双条件，不把“约14天”当一个仅本地日期倒计时。

CometBFT 的证据过期逻辑涉及时间与块数的组合，官方要求说明过旧判断需要两个年龄条件；实现必须测试两个单独超限、两个同时超限与边界值。[S22]

`max_tx_bytes <= max_block_bytes`；`max_spends+max_outputs <= max_proofs_per_block`；投票权总量在指定范围；所有 bps 有效；手续费与 min 金额可表示；创世供给低于技术上界；技术供给上界除以 power_unit 不超过 max_total_voting_power。

## 17.3 本币发行技术边界

参考技术供给上界是 `10^26` 原子单位，以保证金额与投票权可表示；它不是 BTC 式有限发行营销承诺。发行计算接近技术上界时仅发剩余可发行数量，之后额外 mint 为零，奖励只用手续费。金额字段的范围 `<2^120` 则是编码范围，二者不能混淆。

## 17.4 Mainnet 配置必填

独立 chain_id、genesis_time、真实 genesis_manifest_hash、asset id、冻结的 crypto manifest、准确源码/二进制哈希、真实初始验证者与领取公钥、分配金额、初始状态根、资源/发行政策、签名发布者、独立同步端点、真实检查点与审查证据。

`config/mainnet-inputs.template.json` 有意标注尚未提供的外部字段，不会自动生成“批准”结论。主网 build 可以生成程序，但 mainnet init/preflight 在这些材料缺失时应拒绝。

## 17.5 用户本地设置与共识设置分离

用户可修改主题、语言、数据路径、合格查询端点、同步暂停与日志级别；不可通过设置页改本链供给、罚没率、手续费最低额、退出时间或共识阈值。

节点可降低本机接收 mempool 限额、连接数和缓存，但不能因此把协议允许的合法区块判为无效。协议资源上限只来自链规则。

## 17.6 系统阶段资源预算

参考参数每个激活epoch最多1000个pending持仓；超过返回明确错误，不扣款。所有系统与用户阶段共同受逻辑状态写预算控制，实际物理写放大单独测量。候选排名必须增量索引；不得每块无界遍历历史身份、所有账户或所有退出票据。

# 18　架构决策记录（ADR）

## ADR-001 独立链而非现有链上的代币

采用自己创世、自己状态、自己的 PoS 验证网络。依赖开源实现不等于依赖另一条链的安全或手续费。代价是必须建立自己的独立验证权重与安全预算。

## ADR-002 不从零设计共识与曲线

采用受维护 CometBFT 与固定上游密码学组件。复用减少重复实现范围，但所有新组合仍需测试。上游 0.37 的应用示例不可直接拿来声称兼容本项目 ABCI 0.38。

## ADR-003 质押使用公开独立公钥持仓

完整隐藏委托金额会引入额外协议难度；可交易 delegation tokens 又违反单一可流通币目标。因此保持普通支付私密，把质押置于无实名、无支付地址直接绑定但公开持仓生命周期的原生登记簿。此取舍已写进界面与隐私声明，不能改名掩盖。

## ADR-004 无生物识别不等于无授权

取消指纹/面容，采用本地口令、短解锁会话与逐笔确认。服务端无重置钱包资金权限。恢复词与加密备份保留，用户无需日常输入助记词。

## ADR-005 奖励自动计入池资产

用户份额对应价值变化，避免每日领取操作。不创建可流通质押币。退出后按规则领取私密资金仍需本地签名；钱包离线时不假装服务器能自动替它签。

## ADR-006 允许合法释放价值支付费用

为了防止全部锁仓后无法退出，Unbond/Claim/CancelPending 等提供受限释放值支付费用路径。规则必须纳入绑定签名与会计，不开放第三方通用代操作权限。

## ADR-007 不启用跨链、DEX、治理万能入口

整个应用状态机对动作做白名单。软件升级以公开代码与独立参与者选择为基础，不开放项目方随意重置本金/增发的管理员路由。

## ADR-008 轻客户端而非相信单个服务器

钱包验证头、状态证明、compact 摘要及连续性。可信期过期不能自动恢复完全信任，需要新检查点；这项弱主观性边界必须公开。

## ADR-009 保守容量但完整产品

全量功能不意味着无限交易规模。全量本地隐私扫描存在流量成本，正式吞吐 profile 由手机与家庭节点同时测量决定；不得以降低隐私或使用服务端托管来伪装低成本。

## ADR-010 决策变更规则

任何变更记录原因、受影响文档/接口/测试、兼容性与迁移方案。不能为了让测试通过而单独放宽验收或删除失败用例。涉及用户硬性约束的变更不自动实施。

# 附录A　编码与权限补充

# 机器合同的规范性补充

本目录是需要实现的合同。基础密码学字节格式以 D-001/D-003 固定的上游规范、实际参数和验证向量为准；不得用这里的 bytes 类型填随机数据后认为实现完成。

## 编码与 ID

Protobuf envelope 的字段严格按编号递增；repeated 元素顺序有意义，同一 repeated 字段连续编码；默认值按固定生成器规则省略。禁止重复 singular、未知字段、非最短 varint、错误 wire type、未定义 Role、额外签名。解码前严格扫描，解码后重新编码逐字节比较。canonical_body 不能换为 JSON；全体节点只接受唯一编码。CDDL 只定义形状，<2^120、字段间关系、CBOR 最短编码等另有语义检查。

`position_id = SHA256("solo/position/v1" || chain_context32 || owner_pubkey32)`。随机 position_nonce 只用于派生 owner 私钥与恢复收据，不必公开或让节点知道。`validator_id=SHA256("solo/validator/v1"||chain_context32||operator_pubkey32)`。`cohort_id=SHA256("solo/cohort/v1"||chain_context32||validator_id32||exit_epoch_u64be)`。`ticket_id=SHA256("solo/ticket/v1"||chain_context32||position_id32||pre_increment_position_sequence_u64be)`。生成后检查唯一，哈希碰撞不得覆盖旧记录。所有整数在哈希中定长，不拼可变长十进制文本。

## 签名清单

先按输入顺序放 SPEND 授权；随后最多一个 POSITION_OWNER；再 OPERATOR；再 CONSENSUS_POP；再 GENESIS_CLAIM。没有的角色不放空签名。所有授权共同绑定同一64字节 effect_hash；Spend/Binding 采用原上游类型；Ed25519按docs/03第3.11节加各自role_domain。Spend 用上游随机化花费授权，其他公钥为严格 Ed25519。任何多余/遗漏/重复 role,index 都拒绝。

Transfer：仅 Spend 授权。Delegate：新 owner 授权；self_bond=true 额外要求目标验证者 operator 对相同主体签名，且登记自质押绑定。CancelPending/Unbond：当前持仓 owner。ClaimExit：ticket 对应持仓 owner。RegisterValidator：新 operator 和新 consensus PoP。Update/Unjail/ClaimCommission：当前 operator。Rotate：当前 operator 和新 consensus PoP。ClaimGenesis：创世 claim_pubkey。绑定签名独立存在，不替代这些授权。

ClaimExit/CancelPending 的 expected-release 必须等于本次执行状态计算结果，变化即 E_STALE_QUOTE，不用客户端数字制造正余额。ClaimCommission requested-amount 必须正数且不超过已记佣金余额；允许部分领取。ClaimGenesis expected-amount 与创世权利完全相等。Unbond 的 min-gross 仅约束退出内部换算，不授权额外公开释放；RELEASED_VALUE 只释放等于 fee 的部分。

SHIELDED 要求净费用由私密交易价值承担且公开释放额按全额输出；RELEASED_VALUE 允许在公开可领取值内扣费。两者仍执行同一绑定等式，禁止负输出和费用多扣。max-fee>=body.fee。新委托 receipt 必须512字节且非空；节点只能验证长度/主体绑定，无法替用户解密验证收据。

## 普通 memo 与支付请求

私密 memo 固定为 canonical_body 第10项：528字节或 null。上游 v2.1.1 交易级 MemoCiphertext 与 OutputBody.wrapped_memo_key 配套；直接复用加解密与包装，字段参与 effect_hash。普通支付默认带空或有效正文 memo，return_address 每笔派生新地址。一个交易的全部输出共享同一 memo，不开放多收款人差异备注。无输出时为null。上游事实见[S23][S24]。

`solo:<encoded_address>?amount=<8dp_decimal>&network=<chain_context_hex>&invoice=<base64url_128bit>&expires=<unix_seconds>` 为钱包 URI。金额可缺省；不得含私钥、付款签名或执行脚本。拒绝重复金额、负数、指数格式、错误链、未知 req-* 必需字段、超长 URI。普通地址无身份保证；昵称本地保存不替代地址校验。扫描二维码不能自动广播。

发票有随机 invoice_id；付款人在受保护 memo 中携带固定版本结构 (invoice_id、可选订单摘要、可选退款联系信息)，对账只在收款钱包本地完成。公开 API 不建立 invoice_id→付款地址索引。过期发票收到钱仍入账，标记迟到，不自动退款。

## 集合延迟

ValidatorUpdates 在 H 返回，H+2 生效；下一 epoch 首块 H 更新时，退出责任截止为 H+1。不要只写“等14天”而漏掉有效块数和历史集合。该值由实际引擎集成向量确认，参考配置为2。

## 绝不从本合同推导的结论

这里不提供已验证的主网密钥/创世名单，不提供重新生成的生产 ZK 参数，不证明用户匿名或链安全。`bytes`、JSON schema、OpenAPI 校验通过只说明合同结构，不说明密码学实现已完成。

CREATE TABLE validator_changes(chain_context hash32 NOT NULL,height uint64n NOT NULL,event_index INTEGER NOT NULL,validator_id hash32 NOT NULL,change_type TEXT NOT NULL,public_payload JSONB NOT NULL,PRIMARY KEY(chain_context,height,event_index));

## 本轮完成

ClaimGenesis 已从“只有 wire action 和授权角色”接通为完整链上动作。`bit-types` 固定 `claim_id = SHA256("bit/genesis-claim-id/v1" || chain_context || claim_pubkey || amount_be_16)`，拒绝零金额；`bit-transaction` 核对当前领取权、精确金额、未领取状态、GenesisClaim 域签名、费用来源、公开 release、Spend/Output 证明和 binding。

状态升级到 schema v20。`GenesisConfig` 接受公开领取清单，初始化拒绝非法 Ed25519 公钥、错误派生 ID、重复 ID/公钥、零金额和超过 G 容器的分配。按 claim ID 排序的清单摘要写入 `meta/genesis_claims_hash`，每项写入 `genesis/claims/<claim_id>`，成功领取记录共识高度，并与交易、nullifier、TCT、供应审计在同一个 JMT 批次提交。

重启校验会扫描全部领取记录，核对键、派生 ID、公钥、金额、领取高度和不可变配置，并要求“未映射的 G 余额 + 未领取条目总额”精确等于供应容器 G。ClaimGenesis 成功执行 `G -= amount; Q += amount-fee; F += fee`；同块和后续块不能再次释放同一领取权。

真实 Groth16 动作集成测试现覆盖 RegisterValidator、Delegate、Unbond、UpdateValidator、UnjailValidator、RotateConsensusKey、ClaimCommission 和 ClaimGenesis。新增 ClaimGenesis 用例生成真实 2 Spend/2 Output 证明，验证领取公钥签名、binding、费用、供应转换、领取高度、ICS23 成员证明和 RocksDB 重启恢复。轻量授权测试另覆盖错误金额和已领取状态。

只读网关 OpenAPI 升级到 0.3.1。`GET /v1/network` 返回 `genesis_manifest_hash` 与 `genesis_claims_hash` 及同高证明；白名单状态查询允许 `meta/genesis_manifest_hash` 和 `genesis/claims/<claim_id>` 的成员/非成员证明，内部清单或密钥材料不会暴露。OpenAPI YAML 和主网输入 JSON 已用工作区 Python 解析通过。

D-025 已形成首版设计，明确身份输入先产生 `genesis_manifest_hash` 和 chain context，再派生 claim/validator/position ID 与高度零状态，派生结果另行复核，从而消除循环哈希。`config/mainnet-inputs.template.json` 增加领取权和创世承诺输入槽位，并继续保持 `mainnet_ready=false`；没有填入虚构的主网参与者、公钥、金额或签名。

新增 `bit-genesis` crate 与 `bit` CLI。identity manifest v1 使用版本化 canonical CBOR，绑定源码 commit、crypto/参数文件哈希、asset/key/address 版本、资源限制、货币政策、唯一分配映射、领取权、私密承诺、初始验证者和审批阈值。清单哈希和审批签名分别域隔离，解码严格往返；共享向量固定完整 CBOR、manifest hash、chain context、签名消息和 2-of-2 测试签名包。

CLI 已实现 `genesis build|validate|verify|inspect|sign` 和 `release preflight`。分配表是 G0 的唯一计数源，领取权、承诺和自质押必须引用且只能引用同类 allocation，未映射、重复、零金额、错误总额、非法 Ed25519 公钥和未达签名阈值均拒绝。preflight 从证据计算结果，不使用 `mainnet_ready=true` 代替验证；空白主网模板会列出真实缺项并以非零状态退出。新增严格 JSON Schema，模板仍无主网假数据。

identity manifest 与运行时状态之间的首个信任锚已闭合：`GenesisConfig` 必须携带非零 `genesis_manifest_hash`，并强制 `chain_context = SHA256("bit/chain/v1" || genesis_manifest_hash)`。两者在高度零写入同一 JMT、重启逐字节核对，并由 `/v1/network` 返回同一状态版本下的 ICS23 证明。状态 schema 因新增不可变键提升到 v20。
